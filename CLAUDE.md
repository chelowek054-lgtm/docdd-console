# DocDD Console: правила работы в этом репозитории

Инструмент контроля разработки: читает папку `docs/development` выбранного
проекта, строит граф работы и не даёт запустить задачу раньше, чем подтверждены
её документы.

## Главное правило: документ ведёт код

Репозиторий живёт по **Documentation Driven Development (DocDD)** — по тому же
правилу, которое он помогает соблюдать другим:

```
намерение → правка документа → подтверждение человеком → код → сверка
```

**Изменение кода не начинается, пока правка документации не подтверждена
человеком.** Не «показана» — подтверждена.

На практике:

1. Найти документ в `docs/`, который описывает то, что предстоит менять.
2. Внести правку, показать её человеку, назвать, что изменится в коде.
3. Дождаться подтверждения. Молчание подтверждением не является.
4. Написать код — ровно то, что описано, не больше.
5. Сверить: документ и код говорят одно и то же.

Исключения: опечатки, форматирование, переименование внутреннего, починка
дефекта, восстанавливающая уже описанное поведение. Если дефект показал, что
документ описывал не то, — сперва правится документ.

## Что важно не сломать

- **Файлы проекта — источник правды.** Приложение не заводит своей базы и не
  хранит копию данных. Кэш в `.docdd/index.json` удаляется без последствий.
- **Приложение не переписывает текст документов.** Оно меняет только front
  matter и добавляет строки в раздел «Журнал».
- **Приложение не трогает код, не делает коммитов, не создаёт веток и не
  запускает агентов.** Оно отвечает за состояние работы, а не за её выполнение.
- **Сервер работает только внутри объявленного корня проекта.** Любой путь за
  его пределы — отказ, без исключений и без «..» в аргументах.
- **Незнакомые поля сохраняются.** Прочитали, не поняли, записали обратно как
  было — проект вправе добавить своё.

## Как писать код

- TypeScript, строгий режим. `any` — повод объяснить в комментарии.
- Разбор и проверка живут в `server/lib/` и не зависят от Nuxt: это чистые
  функции над строками и объектами, их можно тестировать без сервера.
- Компоненты не ходят в файловую систему — только через API из
  [docs/03-server-api.md](docs/03-server-api.md).
- Комментарий объясняет **почему**, а не пересказывает код.
- Язык интерфейса и документов — русский.

## Проверка

```bash
npm run typecheck
npm run test
npm run lint
```

Работа считается законченной, когда проверки зелёные, документ и код совпадают,
и в изменении нет того, о чём не договаривались.
