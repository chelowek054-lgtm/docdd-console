# Единый дизайн между проектами

Консоль ведёт проекты на разных стеках, и оформление в них разъезжается. Дизайн
ведётся **глобально, в самой консоли**, и спускается в проекты
([adr/0022-design-tokens.md](adr/0022-design-tokens.md)): токены — одним источником,
выгрузка — в файл темы каждого стека, проверка — по экранам проекта. Здесь — формат,
сложение, выгрузка и проверка экранов; как это выглядит на экране — в
[04-ui.md](04-ui.md), «Дизайн»; маршруты — в [03-server-api.md](03-server-api.md).

## Блок `docdd-design`

JSON в теле подтверждённого `design`, как `docdd-rules` ([12-practice-rules.md](12-practice-rules.md)).
Единицы — px (для шрифта — px кегля), без привязки к стеку: выгрузка переводит их сама
(`dp`, `sp`, `pt`, `rem`). Запись может нести несколько блоков, они складываются по порядку.

````
```docdd-design
{
  "principles": [
    "Mobile-first: узкая колонка, отступ по краю 16",
    "Зона нажатия не меньше 44×44",
    "Контраст текста не ниже 4.5:1",
    "Светлая и тёмная темы обязательны"
  ],
  "constraints": { "minTap": 44, "minContrast": 4.5, "gutter": 16 },
  "typography": { "caption": 12, "small": 13, "body": 15, "lead": 17, "title": 22, "display": 28 },
  "spacing": { "xs": 4, "sm": 8, "md": 12, "lg": 16, "xl": 24, "xxl": 32 },
  "radii": { "sm": 8, "md": 12, "pill": 999 },
  "palette": {
    "light": { "bg": "#F4F6F4", "surface": "#FFFFFF", "surfaceAlt": "#E7ECE9", "ink": "#141F1C", "muted": "#516760",
               "line": "#D3DCD7", "accent": "#1B6552", "onAccent": "#FFFFFF", "core": "#835412",
               "ok": "#256A41", "warn": "#7B5911", "danger": "#973024", "onDanger": "#FFFFFF" },
    "dark":  { "bg": "#0E1412", "surface": "#18211F", "surfaceAlt": "#232F2C", "ink": "#E6EDE9", "muted": "#9CB0A8",
               "line": "#334340", "accent": "#6BC2A4", "onAccent": "#08110E", "core": "#E3AD68",
               "ok": "#7CC79A", "warn": "#E5BC74", "danger": "#EE9384", "onDanger": "#2A0F0A" }
  },
  "components": ["TopBar", "Card", "Button", "Field", "Pill", "Progress", "Empty"]
}
```
````

- **Цвета — по ролям, а не по оттенкам:** `accent`, а не `blue`. Роли обязательны в обеих темах.
  Обязательные: `bg`, `surface`, `surfaceAlt`, `ink`, `muted`, `line`, `accent`, `onAccent`,
  `core`, `ok`, `warn`, `danger`, `onDanger`.
- **Шкалы** — обязательные имена: типографика `caption`…`display`, отступы `xs`…`xxl`,
  радиусы `sm`, `md`, `pill`. Недостающее — `design_scale_gap`.
- **Компоненты** — реестр имён, обязательных в каждом проекте. Реестр — договор о
  названиях, а не код: сверка ищет компонент в коде проекта по имени.
- Неизвестные ключи сохраняются, как везде в контракте.

## Где живёт и как приходит

Эталон — подтверждённая запись `design` с блоком `docdd-design` во **встроенном
источнике консоли** `practices/` с тегом `design` ([adr/0015-builtin-practices.md](adr/0015-builtin-practices.md)).
Тот же путь, что у правил практик, и те же правила
([11-shared-sources.md](11-shared-sources.md)): читаются только `approved`, по подключённым
тегам, источник для проекта только для чтения. Проект сверх этого может завести свой
блок в собственном подтверждённом `design`.

**Сложение — «глобальное → проект».** Ключи с одним значением (цвет роли, кегль,
отступ, радиус) **заменяются** проектным; списки (`principles`, `components`) **копятся**.
Заменённая запись (`supersedes`) выбывает. Эталон может закрепить токены полем `"locked"`
блока: `true` — весь блок, или список ключей и их префиксов (`["palette", "spacing.md"]`).
Если проект перекрывает закреплённый токен другим значением — это `design_conflict`:
перекрытие показано, а **действует общее значение**. Каждая часть помнит запись, которая её
задала, — «источник» на экране.

## Проверки токенов

Чистые функции над сложенными токенами, результат — предупреждения раздела «Дизайн»: приходят в ответе `GET /design` и видны на экране
«Дизайн» (в общий список нарушений проекта они не входят):

| Код | Когда |
|---|---|
| `design_contrast_low` | пара «текст/фон» одной темы держит меньше `constraints.minContrast` (по умолчанию 4.5:1, формула WCAG 2.x): `ink`/`bg`, `ink`/`surface`, `muted`/`bg`, `muted`/`surface`, `onAccent`/`accent`, `onDanger`/`danger` |
| `design_theme_incomplete` | роль есть в одной теме и нет в другой |
| `design_scale_gap` | в шкале нет обязательного имени |
| `design_conflict` | проект перекрыл `locked`-токен эталона |

## Выгрузка в стеки

Проект объявляет стеки и пути файлов темы в манифесте:

```yaml
design:
  stacks:
    - { stack: nuxt-ui, files: { css: app/assets/css/main.css, config: app/app.config.ts } }
    - { stack: expo, files: { theme: constants/theme.ts } }
    - { stack: compose, files: { dir: app/src/main/java/ui/theme } }
    - { stack: swiftui, files: { theme: Sources/Theme/Theme.swift, assets: Resources/Colors.xcassets } }
```

Приложение строит из токенов текст файлов — **чистыми функциями, одинаково при каждом
запуске** (тот же вход — тот же текст):

| Стек | Что строится |
|---|---|
| `nuxt-ui` | CSS-переменные ролей для обеих тем (`:root` и `.dark`) в `css`; цвета Nuxt UI в `app.config.ts` (`accent`, `danger`… берут переменные) |
| `expo` | `constants/theme.ts`: `LightColors`, `DarkColors`, `spacing`, `radii`, `typography`; тему выбирает `useColorScheme()` |
| `compose` | `Color.kt` (`LightColorScheme`, `DarkColorScheme`), `Type.kt` (кегли в `sp` → `TextStyle`), `Shape.kt` (`dp`), `AppTheme` над `MaterialTheme` |
| `swiftui` | `Theme.swift` (`Font`, отступы, радиусы) и цвета каталога ассетов `Contents.json` с `Any`/`Dark` |

**Запись в проект — человеком.** Приложение показывает выгрузку рядом с файлом проекта
и дифф; кнопка **«Записать»** кладёт файл — так же, как приложение пишет
`reference/INDEX.md`: файл порождается, правится не руками. Расхождение файла
проекта с выгрузкой — `design_theme_drift` (с диффом); компонент реестра, которого нет в
коде проекта, — `design_component_missing`. Модель файл темы не пишет.

## Проверка экранов моделью

Токены и файл темы могут совпадать, а экран всё равно разъехаться — ловит только взгляд на
сам экран. Проверка идёт по экранам из карты пользовательских путей проекта (`screens`):

1. **Снимки.** Каждый экран — на ширинах 375, 768, 1280 (`design.viewports` в манифесте
   меняет список) в светлой и тёмной теме. Веб — браузер без окна по адресу экрана
   (`design.baseUrl`; адрес экрана — путь из его `id`, если `id` начинается с «/», иначе из
   `design.screens`: `id` → путь); Expo, Android, iOS — эмулятор или симулятор, как объявит проект.
   Снимки лежат в проекте, в `docs/development/screens/`, с описью «экран · ширина · тема ·
   когда снят»; снимок — не запись процесса и в контрактных папках не лежит.
2. **Responsive.** Шаблон `docs/prompts/design-responsive.md`: на каждой ширине нет
   горизонтального скролла, обрезанного и наехавшего, шапка не переносится, зона
   нажатия не меньше `constraints.minTap`, отступ по краю из шкалы.
3. **Pixel-Perfect.** Шаблон `docs/prompts/design-pixel-perfect.md`: снимок против
   сложенных токенов и эталонного макета экрана (`docs/development/screens/<экран>.ref.png`,
   если он есть); каждое расхождение — где, что ожидалось, что на снимке.

Ответ модели — блок `docdd-design-findings` (`screen`, `viewport`, `theme`, `kind` —
`responsive`|`pixel`, `what`). Приложение его разбирает и показывает находками на экране «Дизайн»
проекта (на диске находки не хранятся: это ответ последней проверки); **модель только находит**, исправление — обычной задачей, которую заводит человек. Нет снимка — проверка экрана не идёт, и экран называет, каких
снимков не хватает.
