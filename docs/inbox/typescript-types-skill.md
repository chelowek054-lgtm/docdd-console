# TypeScript: как выбирать типы

Заменяет A-0008 (та же практика, в skill-формате вместо эссе): заведи
decision с `supersedes: [A-0008]`.

Когда: пишешь или ревьюишь типизацию TypeScript-кода.

## Делай

- Аннотируй там, где вывод типов не справляется, — не везде. Явная
  аннотация — там, где она документирует контракт: параметры функций,
  публичные возвращаемые значения.
- Используй `interface` по умолчанию, `type` — когда нужны объединения,
  примитивы, условные типы.
- Держи `noImplicitAny` включённым; `any` — только временная заплатка с
  объяснением рядом.
- Держи `strictNullChecks` включённым всегда; проверяй `null`/`undefined`
  сужением типа, не оператором `!`.
- Выражай ограниченный набор значений объединением (`"left" | "right" |
  "center"`), не строкой без ограничений.
- Используй утверждение типа (`as Type`) редко и осознанно — оно выключает
  проверку, а не подтверждает её.

## Не делай

- Не переусложняй типами то, что и так понятно из структуры.
- Не используй `any`, чтобы «заставить компилятор замолчать», без разбора,
  откуда несовпадение типов взялось на самом деле.
