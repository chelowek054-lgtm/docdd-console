# Агенты ролей — в ядре, для любого типа проекта

Интеграция моделей для работы в любом проекте: выполнение задач, аудит сервиса, критический взгляд, режим дизайнера, маркетолога и т. д. Сейчас роли для запросов — четыре зашитых файла в `docs/prompts/roles`, отвечают только заметкой.

Нужно:

- **Агент — сущность проекта**: роль, системный промпт, модель (из настроенных провайдеров), что ему доступно (читать, предлагать, двигать статусы, работать с кодом в ветке задачи). Создание, правка и удаление через интерфейс; хранится в репозитории проекта рядом с шаблонами запросов.
- **Набор агентов по умолчанию**: архитектор, аналитик, разработчик, тестировщик, DevOps, дизайнер, маркетолог, критик (аудит и критический взгляд).
- **Агент закрывает пустую роль**: в команде проекта роль помечается «за неё работает агент X». Агент может быть исполнителем и ревьюером задачи, а также исполнителем проверки (см. заметку об исполнителе проверки).
- **Движение статусов агентом — через аккаунт агента** (решение для ADR «Делегирование роли агенту»; уточняет ADR-0009, 0011, 0020):
  1. Для агента заводится **аккаунт** в «Аккаунты и доступ», как для человека, но с пометкой «агент».
  2. Аккаунту выбирается **роль** проекта — права те же, что у человека с этой ролью (ADR-0020), проверяет их сервер.
  3. Аккаунту выбирается **тип агента** из подготовленного набора (архитектор, аналитик, разработчик, тестировщик, DevOps, дизайнер, маркетолог, критик): системный промпт, модель, инструменты.
  4. Кнопка **«Запустить в работу»** на задаче (или пачке задач) создаёт агентов назначенных аккаунтов, каждого со своим контекстом: задача и её связи, глобальные правила проекта (CLAUDE.md, практики, вектор, карты), данные самого агента (тип, промпт, его прошлые записи в журнале).
  5. Статусы агент двигает **через API консоли от своего аккаунта**, а не правкой файлов: модель по-прежнему не пишет записи процесса сама, переход применяет приложение под проверкой прав. В журнале — логин аккаунта агента, видно, что это агент.
  - Свою работу агент не принимает (ревьюер ≠ исполнитель, ADR-0030); ручная приёмка от агента помечается как приёмка агентом.
  - Дифф с изменениями внутри `docs/development` по-прежнему не сливается автоматически.
- **Документацию агент пополняет через входящее**: правка документа ложится заметкой, подтверждает человек или ответственная роль.
- **Лимит токенов на задачу** и остановка при превышении.
