# Storybook как контракт компонентов при переносе на другие системы отрисовки

Реализованный Storybook проекта — эталон и контракт базовых и составных компонентов. Он систематизирует и стандартизирует общие решения: каждый компонент описан историями (варианты, состояния, свойства, слоты, события), без бизнес-логики (кроме случаев, когда она неотделима — тогда это сказано явно).

При переносе на другие системы отрисовки (Android Compose, iOS SwiftUI, React Native/Expo, другой web-стек) Storybook — шаблон: перенесённый компонент обязан повторить контракт — те же варианты, состояния и свойства, тот же вид по токенам. Каталоги на других платформах: Storybook React Native, Compose @Preview/Showkase, SwiftUI Previews.

Консоль: читает каталог Storybook (index.json и метаданные историй) в реестр компонентов дизайн-системы — базовые и составные, из чего составной собран; сверяет перенос — у каждого компонента и состояния есть история или превью на каждом объявленном стеке (design_story_missing), свойства совпадают (design_contract_drift); снимки историй из CI проекта — эталон для Pixel-Perfect и визуальных регрессий; запрос модели «перенести компонент на стек» по контракту.
