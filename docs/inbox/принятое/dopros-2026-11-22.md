## 1. Карты: архитектура (5)

- **1.1 Движок 2D.** Mermaid не умеет того, что требует A-0007: ромбы и треугольники UML, кратности на концах, ломаные маршруты, узлы-компоненты с кнопками. Рекомендую: свой рендер на Vue Flow с раскладкой elkjs для всех графовых карт. Mermaid остаётся для выгрузки и для диаграммы последовательностей. 3D остаётся на `3d-force-graph` и получает только цвета групп.
- **1.2 Где лежит определение типа карты.** Рекомендую: файл `docs/development/map-types/<id>.yaml` — в git, переносится копированием. Встроенные предустановки лежат в консоли (`presets/map-types/`). `project.yaml` только включает типы.
- **1.3 Как переопределяется предустановка.** Рекомендую: по частям — `extends: domain`, и меняются только названные ключи.
- **1.4 Цвета.** Рекомендую: в узлах и связях — только токены групп (`ddd.aggregate`, `clean.domain`, `infra.db`, `ui.screen`). Значения задаются в группе отдельно для светлой и тёмной темы. Если контраст ниже AA, консоль предупреждает.
- **1.5 Не-графовые диаграммы, обмен и сверка.**
  - Последовательности — второй движок: из записи собирается Mermaid `sequenceDiagram`.
  - Типами карт делятся копированием файла или через набор практик.
  - Свои типы получают свидетельства и сверку связей, как `docdd-custom` сейчас.

  Рекомендую: да.

## 2. Карты: UX/UI (10)

- **2.5 Тона групп.** Рекомендую: оттенки внутри группы различаются светлотой.
  - DDD — фиолетовые;

  - неизвестное — серый.
- **2.6 Слои чистой архитектуры на карте.** Рекомендую: горизонтальные полосы, `domain` внизу, вместо концентрических кругов — так читается направление «зависимости внутрь» стрелками вниз, и elkjs раскладывает по слоям.
- **2.7 Связи по умолчанию.** Рекомендую:
  - кодовая карта: импорт — тонкая серая сплошная со стрелкой;

- **2.9** Инспектор узла остаётся справа, как сейчас. Рекомендую: да.

## 4. DDD + Clean и многоуровневое модульное деление (20)

- **4.1 Уровни.** Рекомендую:
  - система → контекст → модуль → слой → файл;
  - необязательная «подсистема» над контекстами появляется, когда контекстов больше 7.
- **4.2 Когда делить — пороги.** Рекомендую:
  - модуль: больше 25 файлов или 3000 строк;
  - папка: больше 15 элементов;
  - контекст: больше 7 модулей.

  Пороги настраиваются в `project.yaml`.
- **4.3** Пороги — только предупреждения. Рекомендую: да.
- **4.4** Публичный вход на каждом уровне: модуль — `index.ts`, контекст — тоже `index.ts`. Другие контексты импортируют только вход контекста. Рекомендую: да.
- **4.5** Импорт из другого контекста разрешён, только если связь объявлена в доменной карте; иначе предупреждение `domain_relation_undeclared`. Рекомендую: да.
- **4.6** `shared` не знает контекстов. `kernel` — только доменные типы, общие для нескольких контекстов. Рекомендую: да.
- **4.7 Интерфейс.** Компоненты делятся по контекстам: `app/components/<контекст>/` с префиксом автоимпорта Nuxt. Рекомендую: да, переносить вместе с задачами.
- **4.8 Доменная карта консоли.** Рекомендую: черновик из 8 контекстов:
  1. записи и рабочее пространство;
  2. карты;
  3. проверки;
  4. работа и git;
  5. модель и допрос;
  6. команда и вход;
  7. дизайн;
  8. менеджер и релизы.

  Его составляю я, подтверждаю по 0.1.
- **4.9 Переезд старых файлов.** Рекомендую: после подтверждения доменной карты — отдельные задачи `change: refactor`, по одному контексту на PR. Правило «переезжает, только когда задача его и так меняет» снимается для этих задач.
- **4.10** Имена папок — английские; единый язык — русский, в словаре доменной карты с полем `code`. Рекомендую: да.
- **4.11** Тесты остаются в `tests/` в корне и повторяют структуру папок. Рекомендую: да.
- **4.12** Слои у модуля — по нужде: маленький модуль может быть только `domain` + `application`. Рекомендую: да.
- **4.13** Без DI-контейнера: точка сборки — вход контекста, зависимости передаются параметрами. Рекомендую: да.
- **4.14** Группы кодовой карты строятся автоматически по корням контекстов, если доменная карта есть. Ручные группы остаются для проектов без неё. Рекомендую: да.
- **4.15** Цикл импортов между модулями — предупреждение `module_cycle`. Рекомендую: да.
- **4.16** Размеры для порогов берутся из описи файлов, которая уже есть. Рекомендую: да.
- **4.17** Когда сработал порог, модель предлагает план деления: черновик карты и задачи `refactor`; подтверждает человек. Рекомендую: да.
- **4.18 Пакеты монорепо.** Корень контекста может указывать на пакет workspace. Решение о пакетах — топология, за архитектором; консоль его поддерживает, но не навязывает. Рекомендую: да.
- **4.19 Каркас папок нового проекта.** Каркас контекстов (`domain/application/infrastructure/interface`) заводит модель задачей после подтверждения доменной карты, а не приложение само. Рекомендую: да.
- **4.20** В этом репозитории деление — предупреждениями и вопросом при проверке, без ворот. Рекомендую: да.
