# Транзакции: уровни изоляции PostgreSQL — когда что использовать

Заменяет A-0005 (та же практика, в skill-формате вместо эссе): заведи
decision с `supersedes: [A-0005]`.

Когда: пишешь транзакцию на PostgreSQL, где логика читает и на основе
прочитанного пишет.

## Делай

- **`Read Committed`** (умолчание) — для простых операций с заранее
  известными строками (`UPDATE ... WHERE id = ...`).
- **`Repeatable Read`** — когда транзакции нужен согласованный снимок на всё
  время жизни: несколько чтений видят одни и те же данные.
- **`Serializable`** — когда логическая согласованность важнее
  параллелизма: PostgreSQL сам ловит конфликты, которых `Repeatable Read` не
  видит.
- Ошибку сериализации (`SQLSTATE 40001`) всегда перезапускай транзакцию
  целиком — это ожидаемый исход, не авария.
- Держи транзакции короткими: внутри — только то, что правда нужно для
  целостности.
- Читающую-без-записи транзакцию на `Serializable` помечай `READ ONLY`
  явно.

## Не делай

- Не ставь `Serializable` по умолчанию везде — цена в параллелизме
  оправдана не для каждой операции.
- Не считай ошибку сериализации поводом доверять прочитанным в
  откатившейся транзакции данным.
