# Экономия токенов при работе моделей

- **Фактический учёт**: расход по токенам из ответа провайдера, а не оценка по символам (сейчас на экране «≈ $0.000»).
- **Кэш постоянной части**: вектор, сжатая карта, практики, правила — первыми и одинаковыми в каждом запросе, тогда провайдеры отдают их со скидкой.
- **Дешёвая модель для разбора и сверки** (входящее, сверка пачки, аудит), агент — для кода. Маршруты по виду запроса уже есть — нужны разумные умолчания.
- **Лимит на задачу** для агента, который сам читает репозиторий.
- **Подключение готового проекта** — пачками по описи (как сейчас, по 40 файлов), а не «модель читает всё».
