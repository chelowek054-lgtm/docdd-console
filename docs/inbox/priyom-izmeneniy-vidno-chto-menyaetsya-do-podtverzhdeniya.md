# Приём изменений: видно, что меняется, до подтверждения

Проблема. Кнопка «Подтвердить» стоит над записью, но не видно, что именно подтверждаешь. У карты (M-0052 в learning: 218 файлов за один заход, ~11 тысяч строк блоков) единственный способ понять разницу — читать JSON. То же у любого документа: вектор проекта, требование, задача после правки моделью или человеком, порядок по важности, сложенные токены дизайна. Без видимой разницы подтверждение превращается в «верю на слово», а DocDD держится как раз на осмысленном подтверждении человеком.

Что нужно. Раздел «Приём изменений»: перед подтверждением показывается разница «было → станет», и только после просмотра — «Подтвердить». Подтвердить, не открыв разницу, можно, но экран это отмечает.

Как может выглядеть.

1. Карты — разница на самой схеме, а не текстом. Добавленные узлы и стрелки — зелёные, убранные — красные пунктиром, изменённые (название, слой, группа, родитель) — жёлтые; остальное приглушено. Счётчик сверху: «+41 модуль, −3, ~12; +77 связей». Переключатель «вся карта / только изменённое с соседями». Для кодовой базы и потоков — на всех уровнях вложенности: свёрнутая группа подсвечивается, если внутри есть изменения, и показывает их число. Для функциональной карты — то же в дереве и графе: новая возможность, сменилось состояние «реализовано → частично», новая связь «зависит от». База сравнения — сложенная картина из подтверждённых карт до этой записи; станет — та же картина вместе с ней.
2. Вектор проекта — построчная разница по полям: проблема, для кого, успех, чего не делает; старое зачёркнуто, новое подсвечено. Рядом — какие возможности функциональной карты новый вектор задевает.
3. Документы и задачи — разница текста и полей front matter со времени последнего подтверждения (или со времени, когда запись последний раз видел этот человек): изменённые поля таблицей «поле · было · стало», текст — построчно, связи — «+ implements R-0041, − depends_on T-0090». Источник «было» — git: версия файла на последнем коммите со статусом approved, иначе на предыдущем коммите.
4. Порядок по важности, разбиение на фазы, починка нарушений — уже показываются предпросмотром; их привести к тому же виду «было → станет» (переехавшие фазы и задачи со стрелкой и номером места).
5. Токены дизайна — палитра «было / станет» рядом, контраст до и после, какие файлы выгрузки поменяются.

Общий механизм. Один компонент «разница записи» над любой записью в статусе «на подтверждении», и общий маршрут «что меняется» (было → станет) по типу записи: карта — по сложенной картине, остальное — по тексту и полям. В журнал при подтверждении — строка «подтверждено после просмотра разницы». В списке «на подтверждении» — значок «разница не открывалась».

Чего не делать. Не хранить снимки «было» своей базой: «было» берётся из git и из подтверждённых записей (файлы — источник правды). Не подменять подтверждение автоматикой: разница помогает человеку, решает он.
