# ADR-0022. Единый дизайн: токены в источнике практик, выгрузка без записи в код

- Статус: принято · 2026-10-11
- Дата: 2026-10-11

## Задача

Консоль ведёт проекты на разных стеках: Nuxt + Nuxt UI, React Native + Expo,
Kotlin/Compose, Swift/SwiftUI. Оформление в них разъезжается: каждый объявляет свои
цвета, кегли и отступы. Нужно вести дизайн один раз, в консоли, и спускать в проекты с
проверкой самих экранов (R-0030…R-0033, карта M-0030). Решения этого ADR заранее
оставлены открытыми задачей T-0060.

## Решение

1. **Формат** — блок `docdd-design` (JSON) в подтверждённой записи `design`: принципы,
   типографика, отступы, радиусы, палитра по ролям для двух тем, реестр компонентов,
   `overrides`. Единицы без привязки к стеку ([16-design-system.md](../16-design-system.md)).
2. **Место** — встроенный источник `practices/` с тегом `design`; проект подключает его
   тегом у источника в `sources.shared`, как практики с правилами
   ([ADR-0014](0014-practices-carry-rules.md)). Читается и складывается тем же кодом, что
   `docdd-rules`: общий источник → локальные записи проекта. Нового типа записи нет.
3. **Сложение** — по ключу, поздний уровень заменяет ранний; противоречие — `design_conflict`
   с обеими записями, если ключ не назван в `overrides`. Неявной победы нет.
4. **Файл темы в проект пишет не приложение.** Приложение строит текст и показывает дифф с
   файлом проекта (`design_theme_drift`); меняет файл **задача модели в своей ветке**,
   сливает человек ([ADR-0009](0009-work-through-console.md)). Кнопка «Записать», как у
   `reference/INDEX.md`, тут не годится: `INDEX.md` — производное консоли, а файл темы — код
   проекта, и «код меняет модель, а сливает человек» — инвариант.
5. **Стеки и файлы** объявляет проект в `project.yaml` (`design.stacks`), пути относительно
   корня проекта, умолчания известны выгрузке.
6. **Снимки экранов приложение не делает.** Ему пришлось бы держать браузер и эмуляторы на
   сервере, а на общем сервере ([ADR-0018](0018-shared-server.md)) это лишние привилегии.
   Снимки кладёт проект (сборка, CI, человек) в `docs/development/design/screens/`;
   приложение читает опись и называет недостающее. Скрипт снятия — шаблон текстом.
7. **Находки** модель отдаёт блоком `docdd-design-findings`, человек принимает, приложение
   пишет отчёт `design/reports/…json`; последний отчёт каждого прохода даёт
   `design_screen_finding`. Модель ничего не правит.
8. **Глобальный экран «Дизайн»** — на уровне консоли, рядом с «Все проекты»: эталон, подключившие
   его проекты и сводка находок. «Подключил» — у проекта выбран тег `design` и сложение
   не пустое.

## Что отвергнуто

- **Новый тип записи `token`.** Тип ради пяти частей одного блока; `design` с блоком уже
  подтверждается, связывается и сверяется всем, что есть.
- **Файл токенов JSON в корне проекта (Style Dictionary).** Привязка к инструменту сборки
  каждого стека и второй источник правды рядом с записью. Выгрузка чистой функцией проще.
- **Запись файла темы приложением.** Нарушает «код меняет модель, а сливает человек» и
  делает консоль автором исходников.
- **Снимки через Playwright внутри приложения.** Ни одна из четырёх платформ не покрывается
  одним способом, а часть требует эмулятора; вдобавок это загрузка браузеров на сервер.
- **Автопоиск «лишних» цветов в исходниках.** Ложных срабатываний больше, чем найденного;
  то, что видно пользователю, ловит проверка экрана.
