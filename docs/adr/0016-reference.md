# ADR-0016. Справочник: тип `reference` и индекс для DRY

- Статус: предложено
- Дата: 2026-10-07

## Задача

Модель, которой ставят задачу на новый функционал или рефакторинг, не знает, что в
проекте и вокруг него уже есть: пишет второй модуль рядом с первым, выбирает
библиотеку вместо готовой, что уже стоит, не замечает приём, который в проекте
принят. Практики ([ADR-0015](0015-builtin-practices.md)) отвечают на «как у нас
принято», а не на «что уже сделано» и «что можно взять готовое».

Разбор входящего показал и второй пробел: заметка «справка провайдера» ничего не
порождает, потому что для фактов о внешней системе нет места, — и навсегда остаётся
во входящем.

## Решение

**Новый тип записи `reference`** (префикс `S-`, папка `reference/`): справка о том, что
уже есть снаружи и внутри, с обязательной строкой `summary`, видом, источником и датой.

**Индекс — один короткий файл**, который ведёт приложение: модули проекта из
подтверждённой карты кода плюс внешние решения и приёмы из справок, по строке
«название — что решает → куда смотреть». Он целиком уходит в запрос; подробности
модель читает сама по пути из строки. Размер ограничен, чтобы индекс читали.

**Задачи опираются на индекс**: связь `reuses` (task, design → reference) и поле
`reuse: none` для явного «подходящего нет». Отсутствие обоих — предупреждение, не запрет.

Подробно: [13-reference.md](../13-reference.md).

## Что отвергнуто

- **Справки как `design` с тегом.** Практики вклеиваются в запрос целиком; справка
  провайдера на двадцать килобайт съела бы его. Индекс и тело нужно разделить.
- **Вклеивать справки в запрос целиком.** То же: запрос растёт вместе с проектом.
- **Индекс вручную.** Расходится с картой кода в день написания; его собирает
  приложение из тех записей и карты, которые уже подтверждены человеком.
- **Строка индекса из ответа модели.** Описание модуля — суждение, его подтверждает
  человек в карте (`summary`), а не приложение пересказывает.
- **Запрещать задачу без переиспользования.** Новое бывает по делу; запись «подходящего
  нет» оставляет след, а запрет заставил бы писать формальное.

## Последствия

- Тип `reference`, ключ `paths.reference`, связь `reuses`, поле задачи `reuse` — в
  контракте ([02-workspace-contract.md](../02-workspace-contract.md)) и схемах.
- Файл `reference/INDEX.md` и его сборка; коды `reference_*`, `task_reuse_unchecked`.
- Индекс в запросах: разбор входящего, выполнение задачи, аудит архитектуры.
- Общие источники практики отдают и `reference` по тегам
  ([11-shared-sources.md](../11-shared-sources.md)): встроенный `practices/` может нести
  общий справочник.
- Рефакторинг отдельным видом `change` не заводится: запрос на задачу любого вида,
  кроме `format`, смотрит индекс.
