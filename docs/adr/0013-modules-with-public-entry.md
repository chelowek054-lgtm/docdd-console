# ADR-0013. Система состоит из модулей с публичным входом

- Статус: предложено (ждёт подтверждения человеком)
- Дата: 2026-10-05

## Задача

Карта кода знает файлы и импорты между ними, группы — каталоги, объединённые
по смыслу. Но ни та ни другая не говорит, **как проект должен быть устроен**:
кто вправе обращаться к чьим внутренностям. Правило «между группами ходят
только через публичные модули» в [07-maps.md](../07-maps.md) было отложено
сознательно: публичную поверхность предлагалось объявлять вторым списком, а он
расходится с кодом в тот же день.

Между тем у каждого языка уже есть соглашение, которое отвечает на тот же
вопрос без второго списка: `__init__.py` в Python, `index.ts` в TypeScript
(в FSD это «публичный API среза»), `mod.rs`/`lib.rs` в Rust, пакет-каталог и
`internal/` в Go.

## Решение

**Модуль — каталог с файлом-входом.** Вход определяется по соглашению языка, а не
вторым списком. Всё остальное в каталоге — внутренности. Модули вкладываются:
каталог с входом внутри другого модуля — подмодуль. Из маленьких модулей, каждый
из которых решает свою задачу, складывается модуль крупнее со своей задачей —
и так до системы.

Правила (нарушение — предупреждение, не блокировка; коды в
[05-validation.md](../05-validation.md)):

1. **Через вход.** Снаружи модуля обращаются только к его входу.
2. **Не вверх.** Подмодуль не импортирует своего родителя: родитель собирает
   детей, а не наоборот.
3. **Соседи.** По умолчанию — через вход соседа; строгий режим `via-parent`:
   соседи друг друга не знают, связывает их родитель.
4. **Без циклов** между модулями одного уровня.
5. **Общий код — двух видов.** `shared` — технический, без домена, импортирует
   только себя; `kernel` — общие бизнес-понятия с несколькими владельцами (Shared
   Kernel из DDD), импортирует только `shared`. Метка — место: каталог из
   манифеста, а не комментарий.
6. **Как можно ниже.** Код живёт у единственного потребителя и поднимается до
   ближайшего общего предка всех потребителей; второй потребитель в соседней ветке —
   повод поднять сразу, правило трёх повторов относится к копиям. Глубокий модуль,
   нужный в другой ветке, либо поднимается, либо публикуется через входы вверх, но не
   импортируется в обход (подробно — [07-maps.md](../07-maps.md)).

Слои — профили `architecture.layers`: порядок сверху вниз, импорт только вниз, срезы
`isolated` или `via-entry`. Клиент берёт **FSD** (`isolated`, вход среза —
`index.ts`, бизнес-логика в `model`, переиспользуемое в `shared/ui`); бэкенд —
например `api → modules → platform` со `via-entry`, как принято в модульном монолите
и DDD: бизнес-процессы пересекают модули, и они вызывают друг друга через вход,
событие или порт.

Проверка двухслойная. **Приложение** проверяет правила точно и без модели — по
подтверждённой карте кода, где у каждого импорта уже есть файл, строка и
фрагмент ([ADR-0007](0007-maps-lead-code.md): код не разбирается, сверяются
строки). **Модель** делает аудит того, чего граф не видит (логика в `ui`,
дубли вместо `shared/ui`, модуль с несколькими задачами), и её ответ — мнение:
человек превращает его в задачи ([ADR-0003](0003-no-llm-in-app.md)).

## Что отвергнуто

- **Второй список «публичное» в карте.** Расходится с кодом (см. выше); вход
  по соглашению языка проверяется самим кодом.
- **Блокировать работу нарушением.** Первый прогон на живом проекте даёт много
  находок; пока правила не устоялись, это предупреждения.
- **Разбирать код синтаксическим деревом.** Против ADR-0007, и без того хватает
  импортов из карты.

## Последствия

- Секция `architecture` в манифесте (`entries`, `shared`, `kernel`, `siblings`, `layers`) ([02-workspace-contract.md](../02-workspace-contract.md)).
- Языки без своего входа (Kotlin, Java) не проверяются, пока проект не назвал
  вход; экран говорит «не проверено» с числом, а не молчит.
- Слово «модуль» теперь значит каталог с входом; узел карты кода (один файл) на
  экране называется «файл», а в формате карт остаётся `modules` — переименование
  формата ломало бы подтверждённые записи.
