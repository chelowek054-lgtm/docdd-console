# ADR-0018. Приложение на общем сервере: сервис на localhost, наружу — nginx с авторизацией

- Статус: предложено
- Дата: 2026-10-09

## Задача

Приложение задумано как локальный инструмент: слушает только `localhost`, аутентификации
нет, потому что нет удалённого доступа ([01-architecture.md](../01-architecture.md),
«Безопасность»). Теперь его нужно поставить на сервер Ubuntu вместе с проектом, чтобы
полную картину реализации задач видели и специалисты не из IT, а позже — роли и
исполнитель задачи, как в Jira и Confluence. На сервере порт 80 занят Docker, там же
работает бэкенд.

Смена курса объявлена в карте M-0007: вектор больше не «только на машине пользователя».
Остаётся вопрос, **как** выпустить в сеть приложение, которое умеет менять документы,
запускать модель (через Claude Code на той же машине), коммитить и сливать ветки.
Открытый порт без защиты дал бы это любому, кто до него доберётся.

## Решение

- **Сервис слушает только `127.0.0.1`.** Серверная часть Nitro в сборке по умолчанию
  слушает все интерфейсы, поэтому при запуске задаётся `NITRO_HOST=127.0.0.1`. Правило
  «приложение само не смотрит наружу» сохраняется — меняется только то, кто стоит перед ним.
- **Наружу его открывает nginx на отдельном порту** (по умолчанию 8088), не на 80:
  80 занят Docker. Отдельный файл конфигурации; чужие сайты и конфигурацию nginx
  скрипт не трогает.
- **На входе в nginx — basic auth.** Это временная мера до ролей: один общий вход закрывает
  сервис от случайных и посторонних. Без неё скрипт не ставит доступ по сети.
- **Сервис запускается под systemd под отдельным пользователем** без права входа. Под ним же
  живёт Claude Code, если кнопки модели нужны на сервере.
- **Данные остаются файлами.** Проекты клонируются на сервер отдельно и подключаются по
  пути; список проектов — `.data/` приложения; рабочие деревья задач — `.docdd/worktrees/`
  внутри проекта. Ни базы, ни копии данных не появляется
  ([ADR-0001](0001-files-are-the-truth.md)).
- **Установка и обновление — один скрипт**, который можно запускать повторно
  ([14-deploy.md](../14-deploy.md)). Версия Node берётся из `.nvmrc` в репозитории: один
  источник, а не число в скрипте.

Роли и вход под своим именем — отдельное решение, когда дойдёт очередь
(`access.roles` в карте); оно заменит общий пароль, а не добавится к нему.

## Что отвергнуто

- **Слушать `0.0.0.0` без защиты.** Быстрее всего, но любой, кто видит сервер, может
  править документы и запускать модель.
- **Писать свою аутентификацию сейчас.** Без ролей и пользователей это общий пароль в коде
  приложения, который придётся выбросить; nginx даёт то же за пять строк и не оставляет
  следа в коде.
- **SSH-туннель для каждого.** Закрывает сервис надёжнее всего, но специалисты не из IT
  не будут им пользоваться, а ради них сервер и ставится.
- **Выпустить на порт 80 через общий nginx или Docker.** Порт занят, а ломать работающий
  бэкенд ради инструмента процесса нельзя.
- **Контейнер для самого приложения.** Он потребует прокинуть в него проекты, git и
  Claude Code с их правами; для одного сервиса с одним пользователем это лишний слой.
