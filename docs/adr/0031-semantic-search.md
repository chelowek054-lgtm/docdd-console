# ADR-0031. Глобальный смысловой поиск: эмбеддинги блоков в JSONL и косинусное сходство на сервере

- Статус: принято · 2026-10-22
- Дата: 2026-10-22

## Задача

Поиск по проекту открывал отдельную страницу с пустым полем: чтобы найти документ, надо было уйти
с экрана, где работаешь. Сам поиск был словарным (T-0040): находил только точные слова и их начала,
а «как мы принимаем ручные проверки» не находило ADR-0029, если в нём нет этих слов.

## Решение

1. **Глобальный компонент, а не страница.** Значок-лупа в шапке (и `Ctrl+K` / `⌘K`) открывает окно
   поиска поверх текущего экрана. Пока запрос не введён, ничего не грузится и никуда не уходит.
   Результат — ссылка на блок: запись (задача, требование, документ…) и её раздел.
2. **Блоки, а не файлы целиком.** Запись делится на блоки по заголовкам раздела (`##`, `###`):
   заголовок записи + текст раздела. Так ссылка ведёт к месту, а не к началу длинного документа.
   Источники индекса: записи `docs/development`; входящие заметки — и неразобранные, и разобранные
   (`принятое`); глоссарий `docs/development/glossary.md`; обсуждения у записей (`*.discussion.json`,
   замечание с ответами — один блок, ссылка на запись); документация проекта — `README.md` в корне,
   `docs/**/*.md` вне `docs/development` и папок входящего, и папки `sources.docs` (до 500 файлов по 512 КБ;
   ссылка — на просмотр файла `/projects/:id/file?path=…`). Код (`sources.code`) и практики других
   проектов в индекс пока не входят: для кода нужно другое деление и настоящая модель эмбеддингов.
3. **Хранилище — JSONL в кэше.** `.docdd/embeddings.jsonl`, одна строка — один блок:
   `{ key, recordId, type, title, heading, hash, model, vector }`. Это производное, как
   `.docdd/index.json`: удаляется без последствий и пересобирается (ADR-0001: своей базы нет).
   Пересчитываются только блоки с изменившимся `hash` текста или другой моделью.
4. **Векторы нормализуются при записи** (`‖v‖ = 1`), поэтому косинусное сходство в поиске — это
   скалярное произведение, без пересчёта норм.
5. **Поиск — потоком.** Сервер читает JSONL построчно, пачками по 500 строк, считает скалярное
   произведение с вектором запроса и держит только лучшие N. Память не растёт с размером файла.
6. **Кто считает эмбеддинги.** Если в настройках моделей (`.data/llm.json`, окно «Настройки» → «Поиск») назван провайдер
   эмбеддингов (`embeddings: { provider, model }` — OpenAI-совместимый провайдер и модель эмбеддингов), блоки и запрос
   встраивает он. Иначе — локальный хеш-эмбеддинг `local-hash-v1`: слова и триграммы символов,
   хешированные в 512 измерений. Он работает без сети и ключей и даёт осмысленную близость по
   словоформам; провайдер даёт близость по смыслу. Записи с тегом `confidential` внешнему
   провайдеру не уходят, если он не допущен к закрытым данным: такие блоки в индекс не попадают.
7. **Страница `/search` остаётся** для длинного списка результатов, но шапка на неё больше не ведёт.

## Последствия

Найти можно с любого экрана, не теряя его. Индекс пересобирается сам при смене файлов проекта,
первая сборка на большом проекте занимает время провайдера. Смена модели эмбеддингов полностью
пересобирает индекс: векторы разных моделей несравнимы.
