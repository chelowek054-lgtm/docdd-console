# ADR-0008. Приложение вызывает модель через Claude Code на машине пользователя

**Статус:** принят · 2026-08-31

Отменяет [ADR-0003](0003-no-llm-in-app.md) в части «приложение не обращается к
языковым моделям». Всё остальное из ADR-0003 — что разметку предлагает человек, а
инструмент показывает найденное и применяет утверждённое — остаётся в силе.

## Контекст

ADR-0003 запрещал вызовы модели, и это работало, пока запросов было два: разметка
при импорте и построение карты. Оба редкие, оба делаются раз в проект.

С фазой 7 запросов стало больше, и появился ежедневный: «почини вот эти
нарушения». Переносить текст запроса руками в соседнее окно на каждом круге —
это тот самый признак провала, который назван в [00-overview.md](../00-overview.md):
инструмент, через который медленнее, обходят.

Прежние доводы против вызова из приложения — ключи, сеть, деньги,
невоспроизводимость — все были про **прямой вызов API**. На машине разработчика
уже стоит Claude Code: он авторизован, у него свои лимиты, и он умеет работать
без интерактивного режима.

## Решение

Приложение вызывает модель **через Claude Code на машине пользователя**:
запускает `claude -p` и читает ответ.

1. **Ключей приложение не хранит и не спрашивает.** Авторизация, лимиты и
   стоимость — забота Claude Code и его владельца. В `.data` не появляется ни
   одного секрета.
2. **Сети в приложении нет.** Оно запускает локальный процесс; наружу смотрит
   Claude Code, а не сервер Nitro.
3. **Ответ модели ничего не меняет сам.** Он показывается человеку. Карта
   сохраняется **черновиком** и требует подтверждения, как и любая другая запись;
   починку нарушений приложение не применяет вовсе.
4. **Запрос строится из шаблона в репозитории** ([prompts/](../prompts/)).
   Приложение подставляет данные — список нарушений, состояние карт — и не
   сочиняет текст запроса само.
5. **Claude Code не найден — не поломка.** Кнопка «Спросить модель» неактивна и
   называет причину, а «Скопировать запрос» работает всегда. Прежний порядок —
   отнести текст в своё окно — остаётся рабочим.

## Последствия

- Круг сокращается: нашёл нарушение → получил разбор → починил. Ради этого всё и
  делалось.
- Появляется зависимость от внешней программы, которой может не быть. Поэтому она
  необязательная: без неё приложение работает как раньше.
- Ответы невоспроизводимы: два запроса дадут разное. Это терпимо, потому что
  ответ ничего не решает — решает человек, а карта ещё и сверяется
  свидетельствами ([0007-maps-lead-code.md](0007-maps-lead-code.md)).
- Запуск чужого процесса — новая поверхность. Приложение запускает **только**
  Claude Code, только с текстом запроса, с ограничением времени и размера ответа.
  Ни путей, ни аргументов от пользователя туда не попадает.
- Локальность сохраняется: сервер по-прежнему слушает только `localhost` и сам в
  сеть не ходит.
- Модель запускается в корне проекта, а не в папке сервера: иначе она разбирала
  бы код самого инструмента. Корень берётся из списка проектов, из запроса
  браузера путь не принимается.

## Отвергнуто

**Прямой вызов Anthropic API.** Потребовал бы хранить ключ, знать про модели и
цены, обрабатывать сеть и её отказы. Всё это уже сделано в Claude Code, и делать
второй раз хуже — плохая сделка.

**Оставить как было: только копирование текста.** Честно, но на ежедневном
запросе слишком дорого. Правило соблюдают, пока оно дешевле обхода.

**Применять ответ модели автоматически.** Это сняло бы главное: подтверждение
человеком. Инструмент существует, чтобы код не начинался раньше подтверждения, —
автоприменение сделало бы его тем, против чего он написан.
