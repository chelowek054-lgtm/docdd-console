# ADR-0033. Агенты ролей и делегирование роли агенту

- Статус: принято
- Дата: 2026-10-22
- Уточняет: [0009-work-through-console.md](0009-work-through-console.md), [0011-body-editing.md](0011-body-editing.md), [0020-people-roles-permissions.md](0020-people-roles-permissions.md)

## Задача

Команда не всегда полная: нет тестировщика, аналитика, DevOps. Модель уже умеет работать над задачей в ветке
([ADR-0009](0009-work-through-console.md)), но двигать статусы задач и проверок ей нельзя, а роли для запросов — четыре
зашитых файла, которые только отвечают заметкой. Нужно, чтобы агент закрывал пустую роль — и при этом правило «документ
ведёт код» и «подтверждает человек» не превращалось в украшение.

## Решение

1. **Агент — файл проекта.** `docs/agents/<id>.md`: front matter (`id`, `type`, `title`, `model`, `access`) и тело —
   системный промпт. Файлы проекта — правда ([ADR-0001](0001-files-are-the-truth.md)); консоль своей базы агентов не
   заводит. Набор по умолчанию — восемь типов (архитектор, аналитик, разработчик, тестировщик, DevOps, дизайнер,
   маркетолог, критик); «Создать набор» кладёт их файлами. Создание, правка и удаление — «Настройки → Агенты», право `team`.
2. **Аккаунт агента.** Учётная запись в `.data/users.json` с пометкой `agent: { type }`. Пароля нет, войти через браузер
   агент не может. Роль — строкой в `team` манифеста, как у человека. К API агент обращается по короткоживущему токену
   `Authorization: Bearer`, который консоль выдаёт на один запуск; cookie-сессия и токен агента не взаимозаменяемы.
3. **Права — как у роли, с жёсткими ограничениями** (проверяет сервер, независимо от роли):
   - нет `merge`, `team`, `admin`: сливает и управляет командой человек;
   - нет правки текста документов (`…/records/:id/body`): документацию агент пополняет заметками во входящее;
   - **документы агент не подтверждает никогда**: перевод в `approved` записи, которая не задача (требование, решение,
     проект, контракт, карта, проверка, справка, релиз), массовая смена статуса с такими записями — отказ. Подтверждение
     документов навсегда остаётся за человеком; переключателя нет;
   - свою работу агент не принимает: закрыть задачу (`done`) или отметить «Проверено» по задаче, где он исполнитель, — отказ
     ([ADR-0030](0030-task-reviewer.md)).
   Разрешено в пределах роли: двигать статусы задач, записывать прогоны и «Проверено» по чужим задачам, писать во
   входящее и в обсуждения, назначать исполнителей.
4. **Подпись.** Строка журнала от агента: `- 2026-10-22 · на проверке · QA-агент (qa) · агент`. Видно, что это агент.
5. **Запуск агента по задаче** («Запустить в работу» — агент со своим промптом, контекстом задачи и токеном) — отдельной
   задачей; здесь только сущность, аккаунт, права и подпись.

Без входа (`DOCDD_AUTH` выключен) учёток нет и прав нет — агент работает как прежде через Claude Code, а ограничения
действуют на общем сервере.

## Последствия

- Пустую роль можно закрыть агентом, не выдавая модели права подтверждать документы и сливать код.
- Каждое действие агента подписано и видно в журнале и истории git.
- Правила агентов в коде консоли, а не в проекте: проект не может выдать агенту больше, чем умеет консоль.

## Отвергнуто

- **Переключатель «агент подтверждает документы».** Подтверждение — суть DocDD; команда без человека на роли должна
  найти человека для подтверждения, а не отключить правило.
- **Агент с паролем и входом в браузер.** Агент не человек: долгоживущий пароль — лишний риск, хватит токена на запуск.
