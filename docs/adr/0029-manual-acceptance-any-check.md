# ADR-0029. Ручная приёмка любой проверки; у каждой задачи есть проверка

- Статус: принято · 2026-10-20
- Дата: 2026-10-20

## Задача

Проверка — запись со своим местом в процессе и своим результатом. Отметку «Проверено» человек мог
поставить только у проверок `manual` и `review`, потому что у `unit`, `integration` и `metric`
факт приходит от сборки и ручная отметка «подделывала бы прогон». На практике у проверок вида
`unit` бывает нечем прогнать (нет сборки, тест не написан, проверяли глазами), и запись вечно
висит «не проверена», а задачи за ней нельзя закрыть. Вторая дыра: задача, у которой нет ни одной
проверки, закрывается без препятствий — пустое множество проверок «все пройдены».

## Решение

1. **Ручная приёмка — у проверки любого вида.** Отметка «Проверено» ставится на любой записи
   проверки тем же способом (отчёт `tests/reports` с `runner: manual:<роль>`, строка журнала), но у
   видов `unit`, `integration`, `metric` она **честно помечена**: в отчёте поле
   `verification_kind`, в журнале «проверена вручную (вид unit)», на экране «принята вручную, прогона
   сборки не было». Подделкой это не является, потому что ручной прогон не выдаёт себя за прогон
   сборки: `runner` называет роль, `checked_by` — человека, `note` — что проверено.
2. **Заметка обязательна у автоматических видов** (`note_required`, 400): принимая без прогона,
   человек пишет, на чём основана приёмка. У `manual` и `review` — по-прежнему необязательна
   для API, обязательна на экране.
3. **Последний результат побеждает.** Позднейший отчёт сборки заменяет ручную приёмку, как любой
   новый прогон заменяет прежний; снятие отметки — отчёт `skipped`.
4. **У каждой задачи есть проверка.** Новое предупреждение `task_no_verification`: задача `ready` и
   дальше, у которой через её требования (`implements` → `verified_by`) и собственные `verified_by`
   нет ни одной записи проверки. При включённой политике `require_verification_before_done` перевод
   в `done` без единой проверки блокируется так же, как с непройденной (`task_done_unverified`).
   Проверка — запись, у неё свои статусы документа (`draft` → `approved`) и свой результат
   (`passed`/`failed`/`skipped`/не запускалась).

## Последствия

Закрыть можно любую задачу, у которой проверки пройдены — прогоном или ручной приёмкой с именем и
заметкой. Следы ручной приёмки видны и отличимы от прогонов сборки. Проекты, где задачи без
проверок раньше закрывались, получат предупреждение, а при политике — блокировку перевода.
