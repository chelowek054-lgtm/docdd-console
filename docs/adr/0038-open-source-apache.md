# ADR-0038. Открытый исходный код под Apache-2.0

- Статус: принято · 2026-10-23
- Дата: 2026-10-23

## Задача

Репозиторий закрыт (`"private": true`, файла лицензии нет), а в контент-плане стоял open-core:
открыть формат и проверку, консоль оставить платной. Доход по плану при этом приходит не с
подписки, а с аудита, пилотов, внедрения и обучения. Нужно решить, что открывать и под какой
лицензией.

## Решение

1. **Открыть репозиторий целиком**, включая записи процесса в `docs/development`: проект,
   построенный по собственному процессу, — лучшая витрина подхода.
2. **Лицензия — Apache-2.0** (`LICENSE`, `NOTICE`, поле `license` в `package.json`). Разрешает
   любое использование, как MIT, и добавляет явную патентную оговорку.
3. **Два README**: `README.md` на английском (его GitHub показывает по умолчанию) и `README.ru.md`,
   со ссылками друг на друга в первой строке. Скриншоты — в `docs/assets/`, интерфейс снят на
   английском.
4. **Правила участия** — `CONTRIBUTING.md`: то же правило «документ ведёт код», что и для
   проектов на DocDD; изменение поведения начинается с одобренной правки документа.
   `SECURITY.md` — закрытый канал для уязвимостей. Шаблоны issues и пулл-реквестов — в `.github/`.
5. **Вклад** принимается под той же лицензией (раздел 5 Apache-2.0), без отдельного соглашения.

## Последствия

Код может использовать кто угодно, в том числе для платного сервиса. Для локального инструмента
без своей базы это малый риск по сравнению с выигрышем: доверие к инструменту, который ограничивает
ИИ-агентов, требует видеть, как он это делает. Открытые версии закрыть нельзя; сменить лицензию для
будущих версий можно, пока все авторские права у одного автора.

Почта автора в истории коммитов становится публичной — это основная почта, решение осознанное.

Перед открытием история проверена по шаблонам на ключи API, токены и приватные ключи — найдены
только тестовые заглушки. Публикация репозитория (смена видимости на GitHub) — действие человека.

Отвергнуто:
- **Open-core** (открыта часть) — делит проект и обещания пополам, а платная часть не нужна плану
  доходов.
- **AGPL-3.0** — защищает от облачных клонов, но многие компании запрещают её внутри, это закрыло
  бы пилоты.
- **BSL / FSL** — не open source по определению OSI; сообщество разработчиков встречает такие
  лицензии настороженно.
- **MIT** — то же, что Apache-2.0, но без патентной оговорки.
