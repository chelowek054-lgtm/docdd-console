# ADR-0032. Заведение git-репозитория — только с согласия человека

- Статус: принято
- Дата: 2026-10-22
- Уточняет: [0009-work-through-console.md](0009-work-through-console.md)

## Задача

Формат DocDD живёт в git: история правок, ветки задач и рабочие деревья берутся оттуда. При подключении папки без репозитория
консоль не может вести работу через ветки ([ADR-0009](0009-work-through-console.md)), а человек узнаёт об этом поздно — на первой
задаче. ADR-0009 разрешает приложению с git ровно три действия и «ничего сверх».

## Решение

Добавляем одно действие: **`git init -b main` в папке проекта — только по явной кнопке человека.**

1. При подключении консоль проверяет репозиторий (`GET /api/projects/git-status`). Нет — показывает предупреждение и кнопку
   «Создать репозиторий». Пока репозитория нет, формат не заводится.
2. `POST /api/projects/git-init` требует `consent: true` в теле и право `admin`; путь — внутри разрешённых корней.
3. Больше ничего: ни коммита, ни удалённого адреса, ни отправки. Репозиторий уже есть — ничего не делаем.

Остальное из ADR-0009 в силе: ветка задачи, коммит принятого, слияние перемоткой; без переписывания истории и без отправки на сервер.

## Последствия

- Подключение нового проекта не требует выходить в терминал ради `git init`.
- Консоль не создаёт репозиториев молча: без согласия `consent_required`.
- Первый коммит остаётся за человеком: пустой репозиторий без коммитов — допустимое состояние («Git-репозиторий есть, коммитов пока нет»).
