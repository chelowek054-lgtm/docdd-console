# ADR-0024. Что дизайн-система берёт из статей об UX, UI и дизайн-системах

- Статус: принято · 2026-10-12
- Дата: 2026-10-12

## Задача

Первая редакция формата ([ADR-0022](0022-design-system.md), [ADR-0023](0023-adaptive-by-default.md))
описывала цвета, кегли, отступы, сетку, темы и языки. Четыре материала, которые
человек принёс в раздел, показывают, чего ещё ждёт от дизайн-системы практика:
— «UX.txt»: десять принципов юзабилити (Круг, Нильсен, Маркус);
— «Ux2.txt»: UX и UI вместе, доступность, тренды;
— «DisSys.txt»: дизайн-система «для разработчика» — темы, конструкторы, режимы;
— «DisSys (2).txt»: как складываются дизайн-системы, состав базовых элементов, фазы.

Не всё из них — токены. Одно — формат (что обязано быть в блоке), другое —
проверка, третье — процесс вокруг. Решение раскладывает каждый пункт по месту, а то,
что формат не выражает, превращает в задачи, а не в обещания.

## Решение

**В формат токенов** (проверяется, выгружается, видно на экране):

| Что | Откуда | Зачем |
|---|---|---|
| `fonts` — семейства шрифтов, не больше трёх; обязателен `body` | UX.txt, п. 8 «не больше 3 шрифтов» | Шрифт — токен, а не решение компонента; предел назван |
| `measure` — длина строки в `ch`, 45–80 | UX.txt, п. 8 «50–80 символов на строку» | Читаемость длинного текста задаётся один раз, а не на глаз |
| `border` — толщины линий в rem: `thin`, `thick` | DisSys (2), «базовые элементы: бордеры» | Базовые элементы из практики; без них граница — «на глаз» |
| `icon` — размеры значков в rem: `sm`, `md`, `lg` | DisSys (2), «иконки / изображения» | Тот же довод |
| `motion` — длительности в `ms`: `fast`, `base`, `slow`; при `prefers-reduced-motion` обнуляются в выгрузке | DisSys (2) «анимации»; Ux2 «микроанимации», доступность | Анимация — часть системы, а не украшение; тем, кому она вредит, она отключается сама |
| Роль палитры `focus` и пара «фокус/фон» не ниже 3:1 | Ux2 «навигация с клавиатуры, WCAG 2.1 AA» | Видимый фокус — условие клавиатурной работы; 3:1 — порог WCAG для не текстовых элементов |
| Тема может назвать `minContrast` (по умолчанию 4.5) | Ux2 «высококонтрастный режим» | Контрастная тема проверяется по своему, более строгому порогу (AAA — 7) |
| У компонента реестра `states`, `parts`, `status` | DisSys (2) «слоистое API, состояния default/active/focus/disabled, жизненный цикл» | Компонент без перечня состояний и слоёв нельзя ни проверить, ни стилизовать |
| `Button` и `Field` обязаны нести состояния `focus` и `disabled` | Ux2 доступность; DisSys (2) состояния | Самые частые причины недоступных форм |

**В эталон PRAXIS** — принципы из «UX.txt» (формулировки сжаты, источник назван в записи):
не заставлять думать; не требовать лишнего до показа пользы; один главный акцент на
экране; пустое пространство вместо линий; короткий и простой текст; привычное лучше
нового; ссылки в том же окне; уважение к кнопке «назад»; печатная версия.

**В процесс** — раздел «Как вести дизайн-систему» в [16-design-system.md](../16-design-system.md):
фазы «горячая → синк → плато» из DisSys (2), порядок «исследование → структура →
прототип → проверка» из Ux2 через записи консоли, TETO («тестируй рано и часто») —
как расписание прогонов проверок экранов.

**В очередь, а не в код** (задачи в `backlog`, фаза 41): конструктор тем в интерфейсе
(DisSys), конструкторы форм и таблиц с заготовкой словаря на два языка (DisSys),
режимы «дизайнер»/«разработчик» на экране (DisSys), импорт токенов из Figma Variables
(DisSys (2): «сложно синхронизировать Figma и код»), версионирование токенов
(DisSys (2)). Каждое — отдельное решение, и ни одно не нужно, чтобы формат работал.

## Что отвергнуто

- **Перенести «десять принципов» как проверки.** Из десяти принципов проверяются два-три
  (длина строки, контраст, состояния); остальные — суждение. Они остаются
  принципами эталона, на которые ссылается проверка экрана моделью, а не правилами,
  которые машина выдумывает.
- **Heatmap и юзабилити-тесты внутри консоли.** Это данные внешней аналитики и работа с
  живыми людьми. Консоль принимает их результат как проверку `kind: manual` и отчёт, но
  собирать не берётся.
- **Стили «неоморфизм», «стеклянный морфизм».** Это вкус эпохи, а не свойство системы;
  выражаются отдельной темой и компонентами проекта, если понадобятся.
- **Полная замена UI-кита (как Mantine в DisSys (2)).** Консоль не выбирает библиотеку
  компонентов за проект: она называет, что обязано в нём быть, и сверяет.
