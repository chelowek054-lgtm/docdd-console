# ADR-0019. Несколько языковых моделей через адаптеры; ключи вне репозитория

- Статус: принято · 2026-10-10
- Дата: 2026-10-10

## Задача

Модель сейчас одна: Claude Code на машине пользователя ([ADR-0008](0008-llm-through-claude-code.md)).
Пока консолью пользовался один разработчик, этого хватало. Курс сменился (карта M-0008):
консоль ведёт проекты команды вместо Jira и Confluence, и запросы к модели делают ещё и
менеджер, аналитик, доменный специалист. Им не нужен агент с правом править код, им нужен
ответ по собранному контексту. Кроме того, команда хочет выбирать модель по задаче и по цене:
OpenAI, OpenRouter, RouterAI, локальные модели. Держаться за одного поставщика — значит
остановиться, когда у него кончатся лимиты или поменяются условия.

## Решение

1. **Один интерфейс — много провайдеров.** Провайдер — адаптер с общими кодами отказов
   (`unavailable`, `unauthorized`, `timeout`, `failed`, `empty`, `cancelled`) и общей лентой
   событий. Claude Code становится первым адаптером без смены поведения.
2. **Два вида провайдеров.**
   - **Агент** (`agent`) работает в каталоге проекта с инструментами: Claude Code, потом Codex CLI
     и Gemini CLI. Только им можно отдать работу над задачей, починку и построение карт.
   - **Чат** (`chat`) только отвечает текстом на собранный запрос: OpenAI-совместимый API
     (OpenAI, OpenRouter, RouterAI, Ollama, vLLM) и Anthropic API. Инструментов у него нет,
     и по репозиторию он не ходит: всё нужное ему кладёт пакет контекста
     ([ADR-0021](0021-context-pack.md)).
3. **Маршрутизация по виду запроса.** В настройках сказано, какой вид запроса (разбор входящего,
   план починки, работа над задачей, помощник менеджера…) какой моделью идёт. Запрос, которому
   нужны инструменты, чат-провайдеру не отдаётся: отказ с причиной, а не тихая подмена.
4. **Ключи вне репозитория и вне браузера.** Настройки лежат в `.data/llm.json` и называют ключ
   по имени переменной окружения (`apiKeyEnv: OPENAI_API_KEY`), а не значением. В записи проекта,
   в журнал, в ответ браузеру ключ не попадает. На сервере переменные задаются в юните systemd.
5. **Сеть — только к названным провайдерам.** ADR-0008 обещал «сети в приложении нет». Для
   чат-провайдеров сервер ходит наружу, но только по адресам из настроек. Без настроек всё как
   раньше: работает один Claude Code.
6. **Учёт.** Каждый запрос оставляет строку в `.data/llm-usage.jsonl`: кто, какой вид, какая
   модель, размер контекста, время, оценка цены. Это данные приложения, а не проекта, и они не
   спорят с [ADR-0001](0001-files-are-the-truth.md).
7. **Очередь на сервере.** Запросы команды не могут жить в памяти одной вкладки
   ([ADR-0017](0017-model-jobs-store.md)): задание ставится в очередь на сервере, видно всем, у
   кого есть право, и переживает обновление страницы. Хранилище в браузере остаётся витриной
   этой очереди.

Не меняется: ответ модели ничего не применяет сам, подтверждает человек
([ADR-0008](0008-llm-through-claude-code.md), п. 3). Запрос по-прежнему строится из шаблона в
репозитории.

## Что отвергнуто

- **Общая библиотека-обёртка (LangChain и подобные).** Тяжёлая зависимость ради трёх запросов;
  ленту событий и отказы всё равно пришлось бы приводить к своим.
- **Остаться на одном Claude Code.** Привязка к одному поставщику и к одной машине. Ролям,
  которым не нужен агент, он избыточен и дорог.
- **Ключи в манифесте проекта.** Манифест лежит в git и уходит всем, у кого есть клон.
- **Вызывать провайдера из браузера.** Ключ оказался бы у каждого посетителя.
