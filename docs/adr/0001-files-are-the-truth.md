# ADR-0001. Источник правды — файлы проекта, своей базы нет

**Статус:** принят · 2026-08-30

## Контекст

Инструменту удобно иметь базу: статусы, фильтры, история изменений, быстрые
запросы. Но данные процесса уже лежат в репозитории проекта и живут по правилам
git — ветки, ревью, откаты.

## Решение

Приложение не заводит своего хранилища. Оно читает файлы проекта и пишет в них
же. Единственные собственные данные — список добавленных проектов
(`.data/projects.json`). Индекс в `.docdd/index.json` — кэш: удаляется без
последствий, в git не попадает.

## Последствия

- История ведётся git: кто, когда и что изменил, видно без отдельного журнала
  аудита.
- Смена статуса даёт маленький дифф и обычный конфликт слияния вместо потери
  данных.
- Работа в ветке видна ровно как состояние этой ветки — что и требуется.
- Быстрые выборки приходится делать по индексу в памяти. На тысячах записей это
  не проблема, на сотнях тысяч был бы другой разговор — и другой инструмент.
- Одновременная правка одного файла двумя людьми решается git, а не блокировками.

## Отвергнуто

**SQLite рядом с приложением.** Появляется второй источник правды, который
расходится с файлами в первый же день, когда кто-то поправит markdown руками.

**Только чтение файлов, статусы в базе.** Худшее из двух: статус — самое частое
изменение, и именно оно перестало бы попадать в историю проекта.
