# ADR-0004. Стек: Nuxt 4, Ajv, gray-matter, mermaid, без библиотеки компонентов

**Статус:** принят · 2026-08-30

## Контекст

Приложение маленькое и живёт долго. Каждая зависимость — обязательство
поддерживать её обновления годами, поэтому список должен быть коротким и
обоснованным.

## Решение

| Задача | Чем | Почему именно так |
|---|---|---|
| Каркас | Nuxt 4, TypeScript | Требование к решению; Nitro закрывает доступ к файлам без второго процесса |
| Front matter | `gray-matter` + `js-yaml` | Отдаёт тело файла нетронутым — это условие записи |
| Схемы | Ajv | JSON Schema уже написаны контрактом, второй формат не нужен |
| Разметка | `markdown-it` | Достаточно для показа; расширяется плагином под mermaid |
| Диаграммы | `mermaid` | Формат, в котором диаграммы уже лежат в документах |
| Состояние | `useState` Nuxt | Экранов мало, глобального состояния почти нет |
| Тесты | Vitest | Ядро — чистые функции, тестируются без окружения |

Библиотеки компонентов нет: разметка и немного своих стилей.

## Последствия

- Обновление зависимостей — дело получаса, а не недели.
- Интерфейс выглядит просто. Для инструмента, который открывают на минуту, это
  не недостаток.
- Граф придётся рисовать самим или взять узкую библиотеку в фазе 4 — решение
  отложено до момента, когда станет ясно, какие вопросы задают графу.

## Отвергнуто

**Библиотека компонентов целиком.** Даёт готовые экраны и забирает свободу
вёрстки, а обновления мажорных версий стоят дороже, чем написанные руками
списки.

**Своя реализация разбора YAML и markdown.** Знакомая ловушка: первые две недели
приятно, дальше — вечная починка краевых случаев.
