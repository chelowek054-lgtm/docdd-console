# ADR-0015. Встроенный набор практик

- Статус: предложено
- Дата: 2026-10-05

## Задача

Практики ([11-shared-sources.md](../11-shared-sources.md)) подключаются только
вручную: пока в манифесте нет `sources.shared`, экран «Практики» пуст, а модель
пишет код мимо конвенций стека и правила архитектуры
([ADR-0014](0014-practices-carry-rules.md)) приходится сочинять самому. Для нового
проекта это хуже всего: именно в начале базовые решения (стиль Python, FSD,
принципы кода) нужнее всего, а заводить их с нуля каждый раз — плодить копии.
При этом лучшие практики должны пополнять сами пользователи — значит, встроенный
набор не замена источникам, а то, с чего каждый проект стартует.

Сегодня такие практики лежат среди решений самой консоли
(`docs/development/decisions`, `A-0001…A-0017`), рядом с её собственными: другие
проекты подключают для них весь `docdd-console` целиком, вместе с картами и
решениями, которые к ним не относятся.

## Решение

**Встроенный набор — отдельный DocDD-проект внутри репозитория консоли**:
каталог `practices/` в корне, с собственным `docs/development/project.yaml` и
решениями/проектными записями. Это обычный проект-источник: читается тем же кодом,
что любой источник практик, только для чтения, и редактируется как проект
(своим циклом записи), а не правкой «по месту» в консоли.

**Он подключён сразу.** В `sources.shared` манифеста есть зарезервированный путь
`builtin`. Записи с ним нет — действует неявная `{ path: builtin, tags: [general] }`:
общие принципы приходят в каждый проект без единой правки манифеста. Выбрать
другие теги (`python`, `fsd`, …) — галочками на экране «Практики»: экран тогда
сам добавляет запись `builtin` в манифест. Отключить набор — `tags: []`.

**Он влияет на код так же, как любой источник**: подключённые записи уходят в
раздел «Общие практики» запроса на выполнение задачи, в сверку кода с практиками
и в правила проверки (`docdd-rules`). Отдельного пути для встроенного нет —
иначе он разошёлся бы с остальными источниками.

**Наполнение v1.** Практики переезжают из решений консоли в `practices/` как есть,
со статусами и связями `supersedes`: `A-0001…A-0009` подтверждены, `A-0010…A-0017` —
черновики-преемники, их подтверждает человек. Решения самой консоли остаются в
`docs/development/` консоли.

## Что отвергнуто

- **Копировать практики в каждый проект при заведении.** Копии расходятся с
  первой правки; подключение ссылкой и тегами этого не допускает.
- **Зашить практики в код консоли.** Практики — решения с обоснованием, их читает и
  правит человек, а не релиз приложения.
- **Подключать всё по умолчанию.** Проект на Python не должен получать конвенции
  Vue; поэтому по умолчанию только `general`, остальное — выбором.

## Последствия

- Новый каталог `practices/`, путь `builtin` в `sources.shared`, неявная запись по умолчанию.
- Экран «Практики» всегда показывает встроенный источник первым, с меткой «встроенный».
- Каталог ищется относительно корня приложения; не найден — ошибка у этого
  источника на экране, остальное работает.
- Обновление набора приходит вместе с консолью; проект своё добавляет локальными
  решениями (правила — уровнем «локальное», [12-practice-rules.md](../12-practice-rules.md)).
