# ADR-0039. Тайминги задач — из журнала, а не отдельными полями

- Статус: принято
- Дата: 2026-10-25
- Уточняет: [0001-files-are-the-truth.md](0001-files-are-the-truth.md), [0011-body-editing.md](0011-body-editing.md)

## Задача

У задачи нет срока: его прячут в теги вида `due-2026-10-26`. Журнал пишет только дату, поэтому нельзя посчитать,
сколько задача была в работе, сколько ждала подтверждения документов и сколько висела на проверке. Без этого не видно,
где теряется время, и оценки не учатся на факте.

## Решение

1. **Срок и оценка — поля front matter**, необязательные: у задачи `due: YYYY-MM-DD` и `estimate` (`30m`, `2h`, `1d`),
   у фазы — `due`. Это намерение человека, его не вычислить, поэтому оно лежит в файле. Агент `due` и `estimate` не
   меняет — только предлагает черновиком ([ADR-0033](0033-role-agents.md)).
2. **Факт — из журнала, при чтении.** Строка журнала получает время: `2026-10-25 14:03 · в разработку · architect`,
   местное время по часовому поясу проекта (`project.timezone` в project.yaml). Старая строка без времени читается как
   начало дня. Lead time, cycle time, время в каждом статусе, ожидание подтверждения документов (`documents`,
   `refines`), оценка против факта и просрочка — производные: считаются из строк журнала и связей при чтении. В
   `.docdd` они могут лежать только как кэш.
3. **Правила — предупреждения:** `task_overdue`, `phase_overdue`, `estimate_exceeded` (факт больше оценки вдвое).
   `npm run check` их выводит и не падает.

## Почему не отдельными полями

Поля вида `started_at`, `done_at`, `time_in_review` пришлось бы писать при каждом переходе — второй источник того же
факта, что уже есть в журнале. Он расходится при правке руками, при слиянии веток, при переходе пачкой, и спорить,
какой из двух верен, некому. Журнал уже пишет каждый переход с подписью; добавить в строку время дешевле и честнее,
чем завести параллельный учёт. Тело документа по-прежнему не трогается — меняется только формат дописываемой строки.

## Последствия

- Старые проекты работают как раньше: полей нет — сроков нет; журнал без времени — точность до дня.
- Точность таймингов растёт с момента, когда журнал начал писать время; по старым записям — оценка по дням.
- Контракт ([02-workspace-contract.md](../02-workspace-contract.md)) и схемы (`frontmatter.schema.json`,
  `project.schema.json`) меняются вместе с кодом — первой задачей.

## Отвергнуто

- **Отдельные поля времени в front matter** — второй источник правды (см. выше).
- **Свой журнал событий в базе или `.docdd`** — консоль не заводит своей базы ([ADR-0001](0001-files-are-the-truth.md)),
  а кэш удаляется без последствий.
- **Срок тегом `due-…`** — тег не проверяется схемой и не участвует в правилах; остаётся только как вход для переноса в
  поле.
