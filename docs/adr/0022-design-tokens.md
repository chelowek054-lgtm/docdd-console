# ADR-0022. Единый дизайн: токены в консоли, спуск в проекты, проверка экранов моделью

- Статус: принято
- Дата: 2026-10-11

## Задача

Консоль ведёт проекты на Nuxt + Nuxt UI, React Native + Expo, Kotlin/Compose и
Swift/SwiftUI. Каждый объявляет свои цвета, кегли и отступы, и общий вид держится на
памяти того, кто правил последним. Совпадения файлов мало: токены могут быть верны, а
экран — разъехаться.

## Решение

1. **Токены ведутся глобально, в консоли.** Эталон — подтверждённый `design` с блоком
   `docdd-design` во встроенном источнике `practices/` с тегом `design`: тем же путём,
   что правила практик, а не новой сущностью ([ADR-0014](0014-practices-carry-rules.md),
   [ADR-0015](0015-builtin-practices.md)). Первой записью становится оформление
   PRAXIS из `learning`.
2. **Сложение «глобальное → проект»**, перекрытие `locked`-токена — `design_conflict`.
3. **Спуск — выгрузкой.** Из токенов чистыми функциями строится файл темы каждого из
   четырёх стеков; сверка файла проекта — `design_theme_drift`.
4. **Файл темы записывает человек** кнопкой «Записать» после просмотра диффа; модель его
   не пишет. Приложение уже так пишет `reference/INDEX.md`, и новый путь записи не
   заводится.
5. **Проверка экранов — моделью** по снимкам: Responsive и Pixel-Perfect. Модель
   только находит расхождения; исправление — задача.

## Что отвергнуто

- **Токены в каждом проекте своей записью.** Расходятся с первой правки.
- **Модель пишет файл темы.** Это правка проекта в обход человека; выгрузка
  детерминирована и сразу видна диффом — модель здесь ничего не прибавляет.
- **Проверять только файлы.** Свой цвет в компоненте и скролл на узкой ширине файлами
  не видны.
- **Автоисправление по снимку.** Модель смотрит на пиксели, а не на код: исправление
  без человека — угадывание.

## Последствия

Новый раздел «Дизайн» — глобальный в консоли и в проекте; новые предупреждения
`design_*`; в манифесте проекта — секция `design` (стеки, ширины, адрес). Подробности —
[16-design-system.md](../16-design-system.md).
