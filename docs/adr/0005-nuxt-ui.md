# ADR-0005. Nuxt UI как дизайн-система

**Статус:** принят · 2026-08-30

Пересматривает решение «библиотеки компонентов нет» из
[ADR-0004](0004-stack.md). Остальные пункты ADR-0004 в силе.

## Контекст

ADR-0004 отверг библиотеку компонентов, взвешивая свободу вёрстки против
стоимости обновлений. В этом счёте не хватало третьей величины: вёрстка, которую
пишут руками, требует не решения один раз, а внимания постоянно. Шесть экранов
из [04-ui.md](../04-ui.md) — это списки, карточки, таблицы с фильтрами, модалки,
значки статусов и неактивные кнопки с объяснением; каждый из этих элементов
живёт на нескольких экранах и обязан выглядеть одинаково. Своими стилями это
единство держится на дисциплине, и первое же расхождение приходится чинить
руками во всех местах сразу.

Результат должен быть браузерным приложением для контроля проектов, а не
страницей с данными. Готовые состояния — фокус, наведение, недоступность,
загрузка, пустой список, тёмная тема, доступность с клавиатуры — это работа,
которую при своей вёрстке делают заново и обычно делают наполовину.

## Решение

Интерфейс строится на **Nuxt UI** как дизайн-системе: компоненты, токены
оформления и тёмная тема берутся из неё, а не пишутся заново.

- Компонент библиотеки предпочитается своему всегда, когда он закрывает задачу.
- Своя вёрстка остаётся там, где готового нет: граф записей и карточка записи со
  связями в обе стороны.
- Оформление настраивается токенами библиотеки, а не переопределением её стилей
  снаружи: перекрытая чужая разметка ломается на первом же обновлении.
- Правила интерфейса из [04-ui.md](../04-ui.md) сильнее умолчаний библиотеки.
  Главное из них — недоступное действие показывается с причиной рядом, а не
  просто серым.

Ставится вместе с каркасом в фазе 2 ([06-phases.md](../06-phases.md)): библиотека
компонентов без Nuxt смысла не имеет.

## Последствия

- Экраны выглядят типово и одинаково. Для инструмента, который открывают на
  минуту, это достоинство, а не потеря лица.
- В сборке появляется Tailwind CSS: Nuxt UI стоит на нём и на Reka UI. Это не
  одна зависимость, а слой, и обновления мажорных версий придётся проходить —
  та самая цена, которую называл ADR-0004. Мы платим её осознанно.
- Свобода вёрстки сужается. Там, где библиотека навязывает форму, спорить с ней
  дороже, чем принять: переопределённый компонент — источник поломок при
  обновлении.
- Внешний вид приложения перестаёт быть предметом решений в каждой задаче.
  Это и есть цель: время уходит на состояние работы, а не на отступы.

## Отвергнуто

**Своя вёрстка, как решил ADR-0004.** Даёт полную свободу и требует постоянного
внимания к тому, что не является задачей этого инструмента. Единство экранов при
ней держится на памяти человека — ровно тот способ, который приложение
отказывает признавать надёжным в предметной области.

**Tailwind без библиотеки компонентов.** Снимает вопрос токенов и не снимает
вопрос состояний: модалку, таблицу с фильтрами и доступность с клавиатуры
всё равно пришлось бы писать самим.

**Тяжёлая корпоративная библиотека компонентов.** Закрыла бы те же задачи, но
принесла бы своё представление о приложении целиком. Nuxt UI выбран потому, что
он родной для выбранного в ADR-0004 каркаса и не тянет за собой отдельного
представления о маршрутизации и состоянии.
