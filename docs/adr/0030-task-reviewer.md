# ADR-0030. Ревьюер задачи: явный или по правилу

- Статус: принято · 2026-10-20
- Дата: 2026-10-20

## Задача

Задачу «на проверке» принимает человек, но кто именно — нигде не сказано. Окно «Принять вручную»
по умолчанию подставляло первую роль манифеста, запрос на проверку отдавал «человеку» общий
список без адресата. В итоге задачи висят «на проверке», потому что каждый думает, что смотреть
будет другой. У поля `owner` другой смысл: это роль, которая ведёт запись, а не та, что её
принимает. Принимать свою работу самому — не проверка.

## Решение

1. **Поле `reviewer`** у задачи — роль из `roles` манифеста, которая принимает задачу. Поле
   необязательное, правится `PATCH …/records/:id` наравне с `owner`.
2. **Без поля ревьюер выводится по правилу.** Первое подходящее:
   1. есть проверка вида `manual` → `analyst`: ручная приёмка идёт по тексту требования;
   2. есть проверка вида `review` → `architect`: ревью сверяет с решениями и картами;
   3. есть проверка вида `metric` → `analyst`: метрика сверяется с целью требования;
   4. `change: feature` или `refactor` → `architect`: устройство кода и свидетельства карт;
   5. `change: fix` и прочие → `developer`: второй взгляд разработчика;
   6. запасной порядок: `architect`, `developer`, `analyst`, `pm`.

   Проверки задачи — те же, что у правил: свои `verified_by`, проверки её требований.
   Кандидат пропускается, если совпадает с `owner` задачи (свою работу не принимают) или его нет
   в `roles` манифеста (если роли объявлены). Никто не подошёл — ревьюера нет, и это видно.
3. **Ревьюер виден и используется.** Карточка задачи: «Ревьюер: Аналитик — по правилу: ручная
   проверка» с выбором явной роли. Список задач: метка ревьюера и фильтр «Любой ревьюер» — у роли
   своя очередь приёмки. Окно «Принять вручную» подставляет ревьюера в «Кто принял». Запрос на
   проверку называет ревьюера у каждой задачи и группирует список «человеку» по ревьюерам.
4. **Ревьюер — роль, не человек.** Кто из людей роли принимает, решает команда; правило «не
   исполнитель» действует на уровне роли.

## Последствия

У каждой задачи есть адресат приёмки без ручной разметки 98 задач: правило даёт разумное
значение, поле `reviewer` — исключение. Правило меняется кодом, а не данными: поменять его —
новое решение.
