# Запрос: починить нарушения процесса

Приложение подставляет сюда список нарушений и кладёт готовый текст в буфер или
отправляет его через Claude Code ([adr/0008-llm-through-claude-code.md](../adr/0008-llm-through-claude-code.md)).
Ответ ничего не меняет сам: что с ним делать, решает человек.

---

Ты работаешь с проектом, который ведёт разработку по правилу «документ ведёт
код»: изменение кода не начинается, пока правка документации не подтверждена
человеком. Записи процесса лежат в `docs/development` — требования, документы,
решения, контракты, задачи, проверки, карты.

Ниже список нарушений, которые нашёл валидатор. У каждого код, запись, файл и
объяснение.

<!-- НАРУШЕНИЯ -->

## Что от тебя нужно

Для **каждого** нарушения назови:

1. Причину: что именно в файлах привело к этому коду.
2. Наименьшую починку — правку записи, а не переделку процесса.
3. Чего делать не надо, если починка выглядит соблазнительно, но неверна.

## Границы

- **Не переписывай тело документов.** Приложение меняет только front matter и
  добавляет строку в журнал; предлагай то же самое.
- **Не предлагай отключить правило.** Ошибку нельзя обойти кнопкой — это
  осознанное свойство инструмента, а не недосмотр.
- Номера записей не переиспользуются: удалённая запись оставляет дыру.
- Если нарушение означает, что процесс нарушен по существу — так и скажи. Иногда
  верный ответ: «эту задачу нельзя было закрывать».

Пиши по-русски, коротко, по одному пункту на нарушение.
