# Запрос: аудит архитектуры

Приложение подставляет сюда правила проекта (`architecture` из манифеста), общие
практики, дерево модулей и то, что точная проверка уже нашла. Ответ ничего не
меняет сам и ничего не подтверждает: это мнение, человек читает таблицу замечаний
и сам решает, какие стоит превратить в задачи (docs/07-maps.md, «Модули и
публичный вход»).

---

Система состоит из модулей: каталогов с файлом-входом, которые решают одну
задачу и вкладываются друг в друга. Слои проекта описаны в правилах ниже. Код читай сам —
доступ на чтение у тебя есть, рабочая папка уже корень проекта. Ничего не
меняй: `Edit`/`Write` тебе недоступны, это разовая проверка, а не задача.

**Отвечай за один ход и сам.** Не запускай помощников и фоновые задачи и не
обещай вернуться позже. Код читай выборочно — там, где дерево и названия не
отвечают, и не больше полутора десятков файлов.

## Что от тебя нужно

Найди то, чего граф импортов не видит:

- `logic_in_ui` — бизнес-логика внутри компонента, а не в `model`;
- `duplicate` — повтор вместо переиспользования из `shared/ui` или `shared/lib`;
- `many_tasks` — модуль решает несколько разных задач;
- `leaky_entry` — вход отдаёт наружу всё подряд вместо узкого API;
- `no_entry_use` — внутренность используется снаружи иным способом (динамический
  импорт, строка с путём), хотя статических импортов нет;
- `misplaced` — файл лежит не в том модуле или слое.

Для каждой находки — путь, вид из списка выше и одна фраза простыми словами: что
не так и как поправить. Уверенных находок лучше немного, чем много «на всякий
случай»; не уверен — пропусти.

Формат — один блок JSON, без текста внутри:

````
```docdd-architecture
{
  "findings": [
    { "path": "learningFront/src/features/ielts-writing/ui/Form.vue", "kind": "logic_in_ui", "note": "расчёт оценки считается прямо в компоненте — вынести в model" }
  ]
}
```
````

Перед блоком можно написать пару строк — что показалось неочевидным; после блока
ничего не нужно.
