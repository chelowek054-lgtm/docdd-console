# Запрос: сверить код с общими практиками

Приложение подставляет сюда текст подключённых практик (`sources.shared`,
docs/11-shared-sources.md). Ответ ничего не меняет сам: человек читает
предложенную запись и подтверждает её, как и любую другую
(docs/09-execution.md, «Сверка кода с практиками»).

---

Ты сверяешь код текущего проекта с общими практиками, подключёнными к нему.
Код читай сам — доступ на чтение у тебя есть, рабочая папка уже корень
проекта. Ничего не меняй: `Edit`/`Write` тебе недоступны, и это не задача на
правку, а разовая проверка.

## Что от тебя нужно

Прочитай код проекта и сравни с практиками выше. Один блок JSON — ровно одна
предложенная запись:

````
```docdd-records
{ "records": [ … ] }
```
````

Единственная запись должна быть с `type: "verification"`. Поля:

- `key` — любое понятное имя, например `sverka-praktik`.
- `title` — короткий заголовок с датой сверки не нужен: дата и так есть в
  журнале записи.
- `body` — по каждой практике, с которой код разошёлся: что именно и где
  (файл, если уместно), без общих слов вроде «в целом неплохо». Практик,
  под которые код и так подходит, — не расписывай подробно, одной строкой
  «соответствует» достаточно. Расхождений не нашёл вовсе — так и напиши
  прямо, это тоже ответ, а не повод придумать несуществующее.

Связи (`links`) не нужны: эта запись не привязана к конкретному требованию
или задаче, а описывает состояние всего проекта на момент сверки.
