# Запрос: сверить функциональную карту с кодом

Приложение подставляет сюда список возможностей функциональной карты вместе с
текущей отметкой состояния реализации. Ответ ничего не меняет сам и ничего не
подтверждает: у этого вида карты нет свидетельства, и ответ модели им не
становится — человек читает мнение, не факт (docs/07-maps.md, «"Проверить по
коду" — мнение, не свидетельство»). Приложение разбирает блок ответа в таблицу
«сейчас → по мнению модели»; отметки заносит человек.

---

Функциональная карта описывает, что система умеет, на языке предметной
области — не код, не файлы. Ниже — её текущее дерево, у возможностей уже
стоит отметка состояния, если её кто-то ставил. Код читай сам — доступ на
чтение у тебя есть, рабочая папка уже корень проекта. Ничего не меняй:
`Edit`/`Write` тебе недоступны, это разовая проверка, а не задача.

## Что от тебя нужно

По каждой **нижней** возможности — той, у которой нет подпунктов, — определи,
насколько она реализована в коде. Возможность, разбитую на под-возможности,
отдельно не оценивай: состояние родителя приложение считает по нижним.

Значения `status`:

- `implemented` — реализовано: в коде есть то, что делает возможность целиком;
- `partial` — частично: часть есть, часть нет, и в `note` сказано, чего именно
  не хватает;
- `not_implemented` — не реализовано: код посмотрели и ничего не нашли.

`note` — одна-две фразы простыми словами (карту читают не только разработчики):
что сделано и чего не хватает; файл или модуль можно назвать, номера строк —
нет.

Формат — один блок JSON, по одной записи на возможность:

````
```docdd-functional-check
{
  "capabilities": [
    { "id": "orders.pay", "status": "partial", "note": "оплата картой есть, возврата нет" },
    { "id": "orders.refund", "status": "not_implemented", "note": "в коде нет ни экрана, ни обработчика" }
  ]
}
```
````

`id` бери **ровно как он назван выше**, номера не выдумывай.

**Не уверен — пропусти возможность**: не включай её в блок. «Не нашёл —
возможно, ещё не реализовано, а возможно, названо в коде иначе» — это не
`not_implemented`, а пропуск: прежняя отметка останется как есть, и человек
проверит такое руками. Честный пропуск полезнее уверенного ответа наугад.
`not_implemented` ставь, только когда действительно искал и не нашёл.

Перед блоком можно написать пару строк — что смотрел и где сомневался:
человек прочтёт их рядом с таблицей. После блока ничего не нужно.
