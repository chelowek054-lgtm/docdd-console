# Дополнение к разбору входящего: итог допроса

Приложение добавляет этот раздел к [inbox-plan.md](inbox-plan.md), когда разбирается заметка
завершённого допроса (R-0115, A-0003).

---

## Режим «допрос»: заметка — ответы человека о проекте, разложи их целиком

Заметка выше — дословные ответы человека. Разложи их в документы одним ответом. Что человек не
сказал, не придумывай: это открытый вопрос.

Нужны записи, по порядку:

1. **Запись `map` с `vision` и `capabilities`** — первой. `vision`: `problem`, `audience`,
   `outcome`, `not`, только из ответов. `capabilities`: группы функционала верхнего уровня и
   подпункты, у каждой `"status": "not_implemented"`, если ответ не говорит, что это уже есть.
2. **Запись `map` с полем `domain`** — второй, сразу после стратегической (A-0004): ограниченные
   контексты (`id`, `title`, `kind`: `core`/`supporting`/`generic`, `root` — папка в коде, если
   человек её назвал, `capabilities` — id возможностей из первой записи, `language` — словарь:
   `term`, `meaning`, `code`), агрегаты (`id`, `context`, `title`, `root`, `invariants` — правила
   словами человека, `entities`, `valueObjects`, `policies`) и связи контекстов (`from`, `to`,
   `kind`). Термины и инварианты — только из ответов.
3. **Требования** (`requirement`) — подробное ТЗ. На каждую возможность-лист отдельное. В теле:
   «Зачем», «Что делаем», «Чего не делаем», строка «Готово, когда: …».
4. **Проверки** (`verification`) — к каждому требованию, `links: { "verifies": [ключ требования] }`:
   шаги и ожидаемый результат.
5. **Проектные документы** (`design`) — экраны и пользовательские пути, тон интерфейса: по ответам
   о сценариях и ощущениях.
6. **Решения** (`decision`) — только там, где человек уже сделал выбор: стек, нагрузка, безопасность.
7. **Решения архитектора** (`decision` с `area`: `topology`, `storage`, `transactions`) — по одному на
   область, где выбора ещё нет. Ты **не выбираешь**: в `body` раздел `## Варианты` — минимум два
   варианта (например, модульный монолит и микросервисы), у каждого плюсы, минусы и цена для этого
   проекта по ответам человека. Выбор делает архитектор.
8. **Запись `design` с заголовком «Риски и открытые вопросы»** — обязательно: все подводные камни из
   ответов и **все** открытые вопросы и незакрытые темы из заметки дословно. Ни один не теряется.
9. **Задачи** (`task`, `"change": "feature"`) — маленькими законченными кусками, у каждой
   `links: { "implements": [ключ требования], "affects": [ключ записи map] }`. В `body` задачи
   обязателен раздел `## Ожидаемый результат` с тем, по чему её принимают.
10. **Фаза** (`phase`) — первый фронт работы, `links: { "covers": [ключи задач] }`.

У подключённого проекта не повторяй заведённое и не переписывай его текст: только новые записи и
вопросы, а расхождения с документами — в «Риски и открытые вопросы».

Статусов не ставь: заводятся черновики, подтверждает человек.
