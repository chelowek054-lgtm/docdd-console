# Запрос: разбить задачи на фазы

Приложение подставляет сюда задачи, которые ещё ни в какой фазе, и уже
заведённые фазы ([04-ui.md](../04-ui.md), «Разбить на фазы»). Ответ ничего не
создаёт сам: человек читает список, правит его и нажимает «Создать фазы» —
заводит их приложение, файлы задач при этом не меняются.

---

Ты помогаешь разложить задачи проекта по фазам. Фаза — этап, который можно
довести до конца и показать: после неё что-то работает, а не «сделана
половина». Код и документы читай сам — рабочая папка уже корень проекта.
Ничего не меняй: `Edit`/`Write` тебе недоступны, и это не задача на правку, а
предложение.

## Как раскладывать

- **Порядок задаёт зависимость.** Если задача указывает `depends_on` на
  другую, она в той же фазе или в более поздней — никогда в более ранней.
  Фаза, которой нечего начать без следующей, — неверная граница.
- **Фаза — законченный кусок смысла**, а не корзина по размеру. Задачи одного
  требования (`implements`) обычно идут вместе; общая основа — в первую фазу.
- **Каждая задача — ровно в одной фазе.** Ни одной не терять, ни одну не
  дублировать. Если задача не подходит ни к одной фазе по смыслу — заведи для
  неё отдельную фазу, а не оставляй её без места.
- **Размер разумный**: фаза на две задачи и фаза на пятьдесят одинаково
  бесполезны. Ориентир — от трёх до десяти задач, но смысл важнее числа.
- Задач немного (до четырёх) — одна фаза, и это нормальный ответ.

## Что от тебя нужно

Один блок JSON — список **только фаз**:

````
```docdd-records
{ "records": [ … ] }
```
````

Поля каждой записи:

- `key` — **имя внутри ответа**, любое понятное: `osnova`, `oplata`. Настоящий
  номер (`P-0001`) выдаёт приложение, и придумывать его нельзя.
- `type` — всегда `phase`.
- `title` — короткое название этапа: что после него работает.
- `body` — цель фазы и как понять, что она закончена: несколько предложений
  по существу, а не общие слова.
- `links` — только `covers`: список номеров задач этой фазы, **ровно как они
  названы выше** (`T-0001`). Других связей и других номеров не бывает.

Фазы перечисляй **в порядке выполнения**: первая — та, с которой начинают.

## Как это выглядит целиком

````
```docdd-records
{
  "records": [
    {
      "key": "osnova",
      "type": "phase",
      "title": "Основа: вход и хранение",
      "body": "Пользователь может войти и сохранить данные. Готово, когда сквозной сценарий входа проходит на устройстве.",
      "links": { "covers": ["T-0001", "T-0002", "T-0004"] }
    },
    {
      "key": "oplata",
      "type": "phase",
      "title": "Оплата",
      "body": "Оплата картой в оформлении заказа. Готово, когда платёж проходит в тестовом режиме.",
      "links": { "covers": ["T-0003", "T-0005"] }
    }
  ]
}
```
````

Перед блоком можно написать пару строк — почему именно такие границы: человек
прочтёт их рядом со списком. После блока ничего не нужно.
