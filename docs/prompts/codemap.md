# Запрос: карта кодовой базы

Опиши **изменение** кодовой базы, которое вносит задача, — не состояние проекта
целиком. Ответ — один блок JSON по схеме
[codemap.schema.json](../schemas/codemap.schema.json).

## Что нужно

- `added.modules` — файлы, которые появятся: `id` (путь от корня проекта),
  `title`, `layer`.
- `added.imports` — новые связи между файлами: `from`, `to`, `evidence`.
- `removed.modules` и `removed.imports` — то, что исчезнет. **Не пропускай этот
  раздел**: карта, которая только растёт, через полгода перестаёт быть правдой.

## Свидетельство

У каждого импорта:

```json
{ "path": "server/lib/maps.ts", "line": 3, "fragment": "from './schema'" }
```

- `path` — путь от корня проекта через прямой слеш;
- `line` — номер строки, считая с единицы;
- `fragment` — кусок именно этой строки, по которому видно, что вывод из неё.

Для `added` свидетельство указывает на строку, которая **появится** после
выполнения задачи. Для `removed` — на строку, которая сейчас есть и **исчезнет**.

## Чего не делай

- Не выдумывай строк. Если не уверен в номере — приведи точный фрагмент, сверка
  ищет его в указанной строке и в трёх соседних.
- Не описывай то, чего задача не трогает.
- Не оценивай качество кода: техдолг, дублирование и уязвимости — не эта карта.
