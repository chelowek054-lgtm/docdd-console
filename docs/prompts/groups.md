# Запрос: сгруппировать модули кодовой карты

Приложение подставляет сюда модули общей картины и уже объявленные группы
([04-ui.md](../04-ui.md), «Группы кодовой карты»). Ответ ничего не меняет сам:
он ложится черновиком записи `map`, и группы вступают в силу, когда человек
подтвердит карту ([07-maps.md](../07-maps.md), «Группы: уровень над модулями»).

---

Ты помогаешь разложить модули проекта по группам. Группа — подсистема, которую
можно назвать одной фразой на языке предметной области: «Граф знаний»,
«Аккаунт», «Шлюз к модели». Не слой («ядро», «интерфейс») и не каталог ради
каталога: в группе лежат модули, которые вместе делают одно дело и менялись бы
вместе. Код читай сам — рабочая папка уже корень проекта. Ничего не меняй:
`Edit`/`Write` тебе недоступны, и это не задача на правку, а предложение.

## Уже объявленные группы

Не предлагай их второй раз. Если по смыслу нужно уточнить такую группу —
повтори её `id` с новыми полями: последнее объявление побеждает.

## Как группировать

- **Смысл важнее каталога.** Каталог — подсказка: если `server/lib/graph*` и
  `app/components/GraphView.vue` делают одно дело, они в одной группе, даже
  лежа в разных каталогах.
- **Группа — не корзина, а уровень дерева.** Группы многоуровневые: у группы
  может быть `parent`, глубина любая. На каждом уровне — от 3 до 9 детей
  (подгрупп или модулей). Больше девяти — раздроби на подгруппы; не плоди
  группу из одного ребёнка — это лишний уровень. Сверху вниз: крупные
  подсистемы, внутри них части, в листьях — модули.
- **Границу проводи там, где связей внутри больше, чем наружу.** Если у группы
  наружу связей больше, чем внутри, она нарезана не по смыслу.
- **Каждый модуль — ровно в одной группе.** Не оставляй модули без места, но и
  не дублируй: пересечения группа разрешит не по смыслу, а по порядку записи.
- **Описание — зачем, а не что лежит.** `summary` — две-три фразы для читателя,
  который не открывал код: какую задачу решает группа и кому нужна.
- Заметное большинство модулей ложится по каталогам — это нормально, перечисли
  каталог в `paths`, а не каждый файл. `modules` — только для тех, кто лежит
  не там, где живёт по смыслу.

## Что от тебя нужно

Один блок JSON — только группы, больше ничего:

````
```docdd-codemap
{ "added": { "groups": [ … ] } }
```
````

Поля группы:

- `id` — короткое имя латиницей: `knowledge`, `account`.
- `title` — название на языке предметной области.
- `summary` — зачем группа.
- `paths` — каталоги, под которыми лежат её модули (путь от корня проекта).
- `modules` — `id` модулей, входящих в группу поимённо, если они лежат вне
  `paths`. Только `id` из списка выше.
- `parent` — `id` группы-родителя, если группа — часть более крупной.
  Объявляй многоуровневые группы свободно: родитель сам модулей не перечисляет,
  они лежат в его подгруппах. Цикла по `parent` быть не должно.
- `id` стабилен: уже объявленную группу не переименовывай, повторяй её `id`.
- `capability` — не заполняй: возможности функциональной карты ты не видишь.

Модулей, `imports` и других блоков в ответе быть не должно: приложение примет
только группы.

## Как это выглядит целиком

````
```docdd-codemap
{
  "added": {
    "groups": [
      {
        "id": "knowledge",
        "title": "Граф знаний",
        "summary": "Хранит записи и связи между ними и отвечает на вопрос, что от чего зависит. На нём строятся и граф на экране, и проверка правил.",
        "paths": ["server/lib/graph", "server/lib/links"],
        "modules": ["app/components/GraphView.vue"]
      },
      {
        "id": "account",
        "title": "Аккаунт",
        "summary": "Вход, роли и сессия пользователя.",
        "paths": ["server/lib/auth", "app/pages/login"]
      }
    ]
  }
}
```
````

Двухуровневый случай: у группы `knowledge` две подгруппы, указывающие на неё
через `parent`:

````
```docdd-codemap
{
  "added": {
    "groups": [
      { "id": "knowledge", "title": "Граф знаний", "summary": "Записи и связи между ними." },
      {
        "id": "knowledge-store",
        "title": "Хранение записей",
        "summary": "Читает и пишет записи проекта.",
        "parent": "knowledge",
        "paths": ["server/lib/graph"]
      },
      {
        "id": "knowledge-links",
        "title": "Связи",
        "summary": "Считает, что от чего зависит.",
        "parent": "knowledge",
        "paths": ["server/lib/links"]
      }
    ]
  }
}
```
````

Перед блоком можно написать пару строк — почему именно такие границы:
человек прочтёт их рядом с черновиком. После блока ничего не нужно.
