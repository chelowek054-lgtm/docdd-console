# Пайплайн: ревью моделью, тесты по пирамиде, выкладка и откат, техдолг

Человек на ревью после всей работы модели не успеет физически и станет бутылочным горлышком.

## Решения

1. **Ревьюер по умолчанию — модель:** отдельная сессия сверяет дифф с требованием, проверками и System Design. Человеку уходят только вопросы архитектору: архитектурные расхождения, узкие места, переусложнение. Явный ревьюер-человек (ADR-0030) — по желанию.
2. **Субагенты:** каждый в своей ветке и со своим узким контекстом; один агент собирает результат.
3. **Прогон до приёмки обязателен.** У проверки — случаи по пирамиде: обычные, крайние, невозможные; на каждую проверку — автотест.
4. **Документ не сходится** посреди реализации — модель спрашивает, решает человек.
5. **Релиз** несёт стратегию выкладки (канареечная, по частям, по выборке, вся сразу); «Откатить» с причиной помечает релиз откатанным и возвращает фичи в работу или в бэклог.
6. **Техдолг** — задача `change: debt` в бэклоге с меткой; legacy — откат в никуда (A-0001).
7. Размер задачи не оценивается ни очками, ни часами: его задаёт нарезка.

## Отвергнуто

- Человек-ревьюер на каждой задаче: бутылочное горлышко.
