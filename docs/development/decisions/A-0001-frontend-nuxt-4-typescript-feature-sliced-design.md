# Фронтенд: Nuxt 4 + TypeScript + Feature-Sliced Design

Не про устройство самого DocDD Console — общая практика для клиентской части
других проектов на этом стеке, подключаемая ими через `sources.shared`
([docs/11-shared-sources.md](../../../11-shared-sources.md)). Держится здесь,
а не отдельным проектом: один репозиторий, с которым и так работает каждый
такой проект, проще поддерживать, чем ещё один.

## Зачем это нужно

Каждый новый фронтенд с нуля по своим правилам — ещё один проект, в который
надо заново вникать, прежде чем в нём разобраться. Консистентность между
проектами снижает эту цену: тот, кто писал один такой фронтенд, узнаёт
структуру любого другого.

## Что решили

- Nuxt 4 + TypeScript — базовый стек клиента, не JavaScript и не более ранняя
  версия Nuxt без явной причины.
- Feature-Sliced Design (FSD) — слои `app / pages / widgets / features /
  entities / shared`, зависимости только вниз по слоям, не поперёк и не
  вверх. Доменно-независимое переиспользуемое ядро — в `shared`.
- Nuxt UI как базовая библиотека компонентов, если для конкретного проекта
  явно не решено иначе.
- i18n подключается, если у проекта есть хоть один нерусскоязычный
  пользователь в плане — заводить его задним числом дороже, чем сразу.

## Чего не делаем

- Не мешаем компоненты разных слоёв FSD как попало — `features` не лезет
  напрямую в `entities` другого домена, только через публичный интерфейс
  слоя.
- Не заводим свою альтернативную структуру папок «потому что тут особый
  случай» без записанного решения, почему стандартная не подошла.

## Что мешает

Ничего — конвенция уже проверена на практике (InteractMed, learning/Praxis),
это не гипотеза, а описание того, что уже работает.
