# Допрос по объёму при создании и подключении проекта; подключение через LLM

Этап создания и подключения решает, насколько хорошо проект будет выстроен и стандартизирован. Заменяет черновик A-0006.

## Решения

1. **Правила допроса — по grill-me:** раунды до пяти вопросов, у каждого рекомендованный ответ (он же подсказка новичку), факты модель находит сама, «Не знаю» — открытый вопрос, в конце «Общее понимание» и «Верно».
2. **Уровень по объёму:** малый, средний, крупный; выбирает человек по предложению модели. Даже у скрипта перегонки данных есть стратегия: откуда, куда, зачем.
3. **Порядок нового проекта:** стратегия (что делает, зачем, куда движется) → инженерия (архитектура и профиль, линтеры, CI, DevOps, масштаб, миграции, инфраструктура) → System Design (пользователи, нагрузка, узкие места). Итог — стратегическая, доменная и System Design карты; кодовой нет.
4. **Вопрос о каркасе, линтерах и CI** обязателен при любом объёме: без него проекты берут не те технологии.
5. **Подключение готового проекта через LLM:** человек пишет «интегрируй DocDD», модель находит инструмент по README «Для LLM», ставит его и через MCP получает вопросы подключения; человек отвечает в чате. Модель сначала читает проект и спрашивает только о решениях и противоречиях.
6. **Выбор практик и профиля архитектуры** — шаги допроса (A-0009, A-0016).
7. **След:** сессия — заметка допроса; `project.yaml` хранит первый допрос; записи несут поле `grill`.

## Отвергнуто

- Одна анкета на всё: малому в тягость, крупному мало.
