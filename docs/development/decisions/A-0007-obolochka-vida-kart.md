# Вид карты — настраиваемая оболочка, шаблоны — её предустановки

С картой работают разные люди: архитектор, разработчик, DevOps-инженер, дизайнер. Каждому удобен свой вид. Сейчас вид карт зашит в код: у связей пять фиксированных стилей (ADR-0028), у узлов нет цветовых групп. Новый шаблон и новая область требуют правки компонентов.

## Решения

Зафиксировано со слов chelowek, 2026-11-15:

1. **Оболочка под максимальную настройку.** Всё, что видно на карте, задаёт определение вида, а не компонент:
   - цветовые группы;
   - формы узлов по виду узла;
   - виды связей с параметрами;
   - раскладка;
   - легенда.

   Компонент только рисует по определению.
2. **Каждый цвет — отдельная группа.** Группа — базовый тон и его оттенки, отдельно для светлой и тёмной темы. Узел получает цвет по роли (вид узла, слой, вид контекста). В записи карты цвет не пишется. Группы по умолчанию:
   - **DDD** — свои оттенки: контексты, агрегаты, сущности, объекты-значения, политики, события;
   - **чистая архитектура** — свои оттенки: `domain`, `application`, `infrastructure`, `interface`;
   - **инфраструктура и DevOps** — свой цвет: окружения, развёртывание, CI, базы, очереди, внешние сервисы;
   - **пользовательский интерфейс** — свои оттенки: экраны, компоненты, пользовательские пути.
3. **Стрелки — не просто стрелки.** Вид связи задаёт:
   - линию (сплошная, штрих, точки) и толщину;
   - цвет из группы;
   - наконечники с каждой стороны: нет, стрелка, открытая стрелка, пустой треугольник, ромб пустой и залитый, круг;
   - подпись и кратности на концах;
   - маршрут: прямой, ломаный, кривой;
   - анимацию направления.

   Набор видов связей и их параметры свои у каждого типа карты.
4. **Встроенные шаблоны — предустановки оболочки.** Кодовая, доменная, потоки данных, пользовательские пути и стратегическая карта получают предустановку. Проект может переопределить любую её часть у себя.
5. **Пользователь заводит свои типы карт.** Определение — виды узлов и связей, поля, оформление, раскладка. Оно лежит в файлах проекта, как `maps.custom` сейчас: своей базы нет (ADR-0001).
6. **Стандартные диаграммы ПО.** Среди предустановок есть привычные по учебным курсам:
   - UML: классы, компоненты, развёртывание, пакеты, варианты использования, деятельность, состояния, последовательности;
   - ER;
   - DFD;
   - C4.

   Их можно воссоздать на оболочке без кода.

## Открыто — решается в опросе по картам

1. Где лежит определение вида: в `project.yaml`, отдельным файлом или записью.
2. Как предустановка переопределяется: целиком или по частям, наследованием от встроенной.
3. Диаграмма последовательностей — время сверху вниз, а не граф. Нужен ли ей свой движок рядом с графовым или достаточно Mermaid.
4. Цвета: свободные значения или только токены из групп, ради доступности и тёмной темы.
5. Делиться типами карт между проектами: файлом, практикой или никак.
6. Сверка и свидетельства у своих типов: как у `docdd-custom` сейчас или шире.

## Отвергнуто

- Добавлять стили по одному в код компонентов: каждый новый шаблон снова правит интерфейс.
- Цвет прямо в записи узла: карта перестаёт читаться в тёмной теме, а смена палитры правит записи.
