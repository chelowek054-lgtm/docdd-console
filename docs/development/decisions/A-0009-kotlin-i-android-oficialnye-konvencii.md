# Kotlin и Android: официальные конвенции

Официальный стиль Kotlin (kotlinlang.org) плюс то, что добавляет к нему
официальный стиль Android (developer.android.com) сверху — не свой стиль
с нуля.

## Зачем это нужно

Kotlin оставляет много свободы в стиле (точка с запятой не обязательна,
фигурные скобки не всегда нужны), и без единого решения каждый файл может
выглядеть написанным разным человеком — в буквальном смысле, если писал
разный человек.

## Что решили

- **`val` вместо `var`**, пока переменная правда не переприсваивается.
  Неизменяемые коллекции (`listOf`, не `arrayListOf`) — по умолчанию.
- Имена: пакеты — строчными без подчёркивания (`org.example.project`),
  классы — `PascalCase`, функции/свойства/переменные — `camelCase`,
  константы верхнего уровня или в `object` — `UPPER_SNAKE_CASE` с
  модификатором `const`.
- 4 пробела на отступ, открывающая скобка на той же строке (K&R), не
  Allman.
- **Импорт без `*`** — список одной группой, отсортирован.
- **Функция из одного выражения — телом-выражением**: `fun f() = x`, не
  `fun f() { return x }`.
- Именованные аргументы — для `Boolean`-параметров и там, где несколько
  параметров одного примитивного типа подряд: `drawSquare(x = 10, y = 10,
  fill = true)`, а не `drawSquare(10, 10, true)`, где по месту не видно,
  что есть что.
- KDoc — для каждого публичного типа и публичного/protected члена, кроме
  самоочевидных (`getFoo`) и переопределений.
- Файл Android-проекта — по имени единственного публичного класса; файл на
  несколько объявлений — по общей теме, не как попало.
- 100 знаков — предел строки на Android (Kotlin сам предела не задаёт).

## Чего не делаем

- Не используем `!!` как обычный способ снять nullable — только когда
  отсутствие `null` доказано логикой, которую компилятор не видит, и это
  видно из контекста.
- Не пишем цикл `for` там, где `filter`/`map`/`forEach` читается яснее —
  но не наоборот: явный цикл понятнее сложной цепочки, которую придётся
  расшифровывать.
