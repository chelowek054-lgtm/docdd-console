# MCP — тонкий слой над API консоли, новые возможности — модулями с публичным входом

Ассистенты должны работать с проектом, не обходя правила DocDD. Если MCP-сервер сам будет читать и писать файлы, появится второй путь мимо ворот и прав, и правила разойдутся. Поэтому MCP-сервер — отдельный процесс `cli/mcp.ts` по stdio, который ходит только в HTTP API консоли. Правила, права и журнал остаются в одном месте.

Что следует из решения:

1. **Подтверждать через MCP нельзя.** Инструментов подтверждения записи, закрытия задачи и слияния нет вовсе. Инструмент смены статуса пропускает только белый список переходов.
2. **Запись только со входом.** Ограничения агентов ADR-0033 действуют при включённом `DOCDD_AUTH`. Без него API не отличает агента от человека, поэтому MCP работает только на чтение.
3. **Токен не уходит модели.** Токен агента лежит в окружении процесса и в ответы инструментов не попадает.
4. **Модули.** Новые возможности лежат в `server/lib/<модуль>/` с входом `index.ts` (ADR-0013). Модуль объявляет свои инструменты в реестре. Новый инструмент — новый файл модуля, а не правка сервера.
5. **Старый код не переносим разом.** 106 файлов `server/lib` переезжают только когда их и так меняет задача: массовый перенос до 1.0.0 — риск без пользы для пользователя.

Отвергнуто: прямой доступ MCP к файлам — второй путь мимо правил; встроенный в Nuxt HTTP-транспорт MCP — на старте не нужен и добавляет поверхность для атаки.
