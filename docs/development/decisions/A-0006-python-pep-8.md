# Python: PEP 8

Официальный стиль Python, а не свой. Смысл не в конкретных цифрах (их даёт
источник и линтер), а в том, что стиль — один на все Python-проекты этого
стека, не придумывается заново.

## Зачем это нужно

PEP 8 сам формулирует главное: код читают намного чаще, чем пишут. Разный
стиль в разных Python-проектах — цена на каждое переключение между ними.

## Что решили

- 4 пробела на уровень отступа, без табов.
- Длина строки — по умолчанию PEP 8 (79 знаков для кода); проект вправе
  договориться о своём пределе явно, а не молчаливым расхождением.
- Имена: `snake_case` для функций и переменных, `PascalCase` для классов,
  `UPPER_SNAKE_CASE` для констант, ведущее подчёркивание — сигнал
  «не для внешнего использования».
- Импорты — отдельными строками, сгруппированы (стандартная библиотека →
  сторонние → локальные), без `import *`.
- `is`/`is not` для сравнения с `None`, `isinstance()` вместо сравнения
  типов напрямую.
- Docstring — для каждого публичного модуля, класса, функции.
- Форматирование и порядок применяются автоматически линтером
  (`ruff`/`black` или эквивалент), а не вычитыванием глазами: спор о
  пробеле — не то, на что тратится время ревью.

## Чего не делаем

- Не жертвуем читаемостью ради буквального соответствия — сам PEP 8
  разрешает «знать, когда быть непоследовательным».
- Не ломаем обратную совместимость ради переформатирования уже
  существующего кода без причины.
