# Встроенная практика DDD + Clean

Зачем: основа одна для всех проектов (A-0004). Без правил в наборе консоль не может ни подсказать модели, ни заметить уход от основы.

Что делаем:
- Во встроенный набор `practices/` добавляется решение «DDD + чистая архитектура» с тегом `general`, то есть включено у всех проектов по умолчанию.
- Решение несёт блок `docdd-rules` с профилем `ddd-clean`. Слои `domain`, `application`, `infrastructure`, `interface` с корнем `{root}`: зависимости только внутрь, `infrastructure` и `interface` друг от друга независимы, `domain` не импортирует фреймворки и драйверы базы (`forbidden`).
- Профиль применяется к каждому контексту доменной карты (R-0119) по его корню. Руками через `use` — как раньше.
- Решение описывает паттерны A-0004 по одному абзацу с примером «рейс и ведомость»: сущность, объект-значение, агрегат с корнем, политика, доменное событие, репозиторий, прикладной слой без правил, единый язык. Этот текст уходит модели вместе с остальными практиками.
- Статически консоль проверяет только направление зависимостей. Соблюдение паттернов проверяет аудит архитектуры моделью: у сущности нет произвольных сеттеров, правило не утекло в прикладной слой, объект-значение не мутирует, агрегат меняется только через корень. Выводы аудита — тоже предупреждения.
- Нарушения выходят существующими кодами `arch_layer_up`, `arch_forbidden`, `arch_slice_cross` и остаются предупреждениями.

Чего не делаем: не блокируем задачи, не правим чужой код, не навязываем имена папок — имя слоя можно переопределить в профиле проекта.

Готово, когда: у нового проекта без своих правил профиль виден на экране «Практики». Импорт `domain` → `infrastructure` внутри контекста даёт предупреждение `arch_layer_up` в `check` и в аудите. `tags: []` у `builtin` отключает практику.
