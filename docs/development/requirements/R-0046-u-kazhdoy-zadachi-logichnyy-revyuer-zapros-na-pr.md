# У каждой задачи логичный ревьюер; запрос на проверку следует ADR-0029 и адресует человеку по ревьюерам

У задачи есть ревьюер — роль из манифеста, которая её принимает (ADR-0030): явное поле reviewer (правится PATCH наравне с owner, незнакомая роль — 400 reviewer_unknown) или правило: проверка manual → analyst, review → architect, metric → analyst, change feature/refactor → architect, иначе developer, затем запасной порядок architect, developer, analyst, pm; роль, совпадающая с owner или отсутствующая в манифесте, пропускается. Ревьюер виден в карточке задачи с причиной и выбором явной роли («по правилу» убирает поле), в строке списка задач, фильтр «Любой ревьюер» сужает список и запрос на проверку; окно «Принять вручную» подставляет ревьюера в «Кто принял». Запрос на проверку называет ревьюера у каждой задачи, следует ADR-0029 (без проверки не закрывать, ручную приёмку ставит только человек, общая проверка закрывает все задачи требования «на проверке», в done только из in_review) и группирует список «человеку» по ревьюерам. Готово, когда у каждой задачи на экране есть ревьюер или явное «ревьюера нет», а запрос на проверку содержит строку «Ревьюер:» у каждой задачи.
