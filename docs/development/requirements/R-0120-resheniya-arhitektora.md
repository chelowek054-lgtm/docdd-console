# Решения архитектора: топология, хранение, транзакции

Зачем: выбор между монолитом и микросервисами, способ хранения данных и место транзакций дорого переделывать и нельзя решать методом. Это зона архитектора (A-0004).

Что делаем:
- У записи `decision` появляется необязательное поле `area`: `topology`, `storage`, `transactions`. Схема front matter его принимает.
- Перевести такое решение в `approved` может только человек с ролью `architect`. Остальным сервер отвечает `403 architect_only`, в том числе при массовой смене статуса. Без входа (личный режим) правило не действует: роль одна — сам человек.
- Предупреждение `arch_decision_missing`: в проекте есть доменная карта, а по области нет ни одного решения, даже черновика. Одно предупреждение на область.
- Модель такие решения не принимает. В раскладке допроса, разборе входящих и на «Что хотим?» она заводит по пробелу черновик с разделом `## Варианты`: минимум два варианта, плюсы, минусы и цена каждого, без выбора. Ответ модели, где у такого черновика выбран вариант, консоль не блокирует, но запись остаётся `draft` до архитектора.

Чего не делаем: не советуем конкретную базу или топологию от себя, не трогаем решения без `area`.

Готово, когда: разработчик получает `architect_only` на подтверждение решения с `area`, архитектор подтверждает; `check` напоминает о пустой области; запрос раскладки просит варианты, а не выбор.
