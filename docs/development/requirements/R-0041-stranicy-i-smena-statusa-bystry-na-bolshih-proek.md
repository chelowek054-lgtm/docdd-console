# Страницы и смена статуса быстры на больших проектах

На больших проектах (сотни записей, тысячи файлов кода) смена статуса занимала около 10 секунд, страницы карт и задач открывались долго: каждая операция заново читала и разбирала все записи, обходила дерево кода и запускала git, а карта, правила и дизайн делали то же. Требуем: разбор файла записи кэшируется по пути, времени изменения и размеру; запрос читает проект один раз (один снимок на смену статуса, правку тела и отметку «проверено»); производные ответы (карта, правила, справка, дизайн) запоминаются по отпечатку индекса; экран после смены статуса обновляет строку из ответа, а не перечитывает весь индекс; тяжёлые данные страниц подгружаются лениво, длинные списки показываются порциями. Готово, когда смена статуса не делает больше одного чтения проекта, а повторное открытие страницы без изменений файлов не пересчитывает ничего тяжёлого. Файлы проекта остаются источником правды: кэш производный и удаляется без последствий (ADR-0001).
