# Требования к качеству с цифрами

Зачем: без цифр нагрузки и надёжности решения архитектора — вкусовщина, а проверить их нечем (A-0005, п. 1, 4).

Что делаем:
- У записи `requirement` необязательное поле `quality`: `load`, `latency`, `availability`, `recovery`, `data`, `security`, `observability`. Схема front matter его принимает.
- Предупреждение `quality_unmeasured` у подтверждённого требования к качеству:
  - `load`, `latency`, `availability`, `recovery`, `data` — нет ни одной проверки вида `metric`;
  - `security`, `observability` — нет ни одной проверки.
- Список требований показывает метку качества.

Чего не делаем: не разбираем число из текста и не сравниваем с метрикой сами — это уже делает прогон проверки-метрики (R-0065).

Готово, когда: схема принимает семь значений и отвергает иное; `quality_unmeasured` появляется на своих случаях и молчит, когда проверка есть; у требования в списке видна метка.
