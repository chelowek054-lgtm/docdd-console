# Выгрузка токенов в четыре стека и сверка проекта с токенами

Зачем: токены дают единый вид, только если каждый стек берёт значения из них, а не переписывает руками; иначе расхождение начинается с первой правки в одном из проектов.

Нужно: проект объявляет, на каких стеках он собран и где лежит его файл темы (`nuxt-ui`: `main.css` с переменными и `app.config.ts` с цветами Nuxt UI; `expo`: `constants/theme.ts` со светлой и тёмной палитрой, отступами и кеглями под `useColorScheme()`; `compose`: `Color.kt`, `Type.kt`, `Shape.kt` и `AppTheme`; `swiftui`: `Theme.swift` и цвета каталога ассетов с Any/Dark). Приложение строит из токенов текст этих файлов — чистыми функциями, одинаково при каждом запуске — и показывает его рядом с тем, что лежит в проекте. Расхождение — предупреждение `design_theme_drift` с диффом; компонент из реестра, которого нет в коде проекта, — `design_component_missing`. Как файл темы попадает в проект (пишет человек кнопкой, приложение само или задача модели) — решается ADR раздела.

Готово когда: для каждого из четырёх стеков есть выгрузка, покрытая снимком; проект, чей файл темы отстал от токенов, видит `design_theme_drift` и дифф.
