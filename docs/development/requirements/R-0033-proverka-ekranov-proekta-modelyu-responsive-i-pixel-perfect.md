# Проверка экранов проекта моделью — Responsive и Pixel-Perfect

Зачем: токены и файл темы могут совпадать, а экран всё равно разъехался — свой цвет в компоненте, отступ на глаз, шапка, которая ломается на узкой ширине. Совпадение файлов этого не ловит; ловит только взгляд на сам экран.

Нужно: глобальный дизайн спускается в проект **с проверкой по экранам**. Экраны проекта берутся из карты пользовательских путей (`screens`). Для каждого экрана снимаются снимки на заданных ширинах (по умолчанию телефон 375, планшет 768, десктоп 1280) в светлой и тёмной теме, и модель проверяет их двумя проходами: **Responsive** — на каждой ширине нет горизонтального скролла, ничего не обрезано и не наезжает, шапка не переносится, зона нажатия не меньше 44×44, отступ по краю — из шкалы; **Pixel-Perfect** — экран сверяется с эталоном: токенами (цвета ролей, кегли, отступы, радиусы) и эталонным макетом экрана, если он есть, — и называет каждое расхождение: где, что ожидалось, что на снимке. Находки — записи с экраном, шириной и темой, видны в «Сверке» проекта и сводкой на глобальном экране «Дизайн». Модель только находит: ничего не правит, исправление — обычной задачей.

Готово когда: для проекта со снятыми экранами проверка выдаёт находки по Responsive и Pixel-Perfect с экраном, шириной и темой; экран без нарушений проходит чисто; нарочно испорченный цвет или отступ находится.
