# MCP-сервер консоли — работа с проектом без обхода правил

Зачем: ассистент должен вести проект через консоль и получать короткие готовые ответы, а не читать папку целиком.

Что делаем: процесс `cli/mcp.ts` (stdio), который обращается только к HTTP API консоли.

- Чтение: `project_status`, `next_tasks`, `task_context`, `list_issues`. Каждый ответ ограничен бюджетом и сообщает, что отрезано.
- Запись (только при `DOCDD_AUTH`, от лица агента): `create_draft`, `add_journal_line`, `move_task` — только `ready → in_progress` и `in_progress → in_review`.

Чего не делаем: подтверждение записей, закрытие задач, слияние, правка текста подтверждённых записей, доступ к файлам мимо API, сетевой транспорт MCP.

Готово, когда: ассистент по MCP находит задачу, получает контекст, берёт её в работу и сдаёт на проверку; попытка подтвердить или слить невозможна: такого инструмента нет.
