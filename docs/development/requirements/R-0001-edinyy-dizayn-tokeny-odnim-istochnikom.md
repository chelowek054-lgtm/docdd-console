# Единый дизайн — токены одним источником на все проекты

Зачем: консоль ведёт несколько проектов на разных стеках (веб на Nuxt + Nuxt UI, кроссплатформа на React Native + Expo, натив на Kotlin/Compose и Swift/SwiftUI), и оформление в них разъезжается: каждый проект объявляет свои цвета, кегли и отступы, и общий вид держится на памяти того, кто правил последним.

Нужно: дизайн ведётся **глобально, в самой консоли**, и спускается в проекты, а не заводится в каждом. Он описывается **токенами** в одном месте — подтверждённой записью `design` с блоком `docdd-design` во встроенном источнике консоли `practices/` (тот же путь, что у правил архитектуры: подключение по тегам, только `approved`, в проекте — только для чтения). Глобальный экран **«Дизайн»** — на уровне консоли, рядом с «Все проекты», а не внутри проекта: там видно эталон и какие проекты его подключили. Блок несёт пять частей: принципы и ограничения (mobile-first, зона нажатия не меньше 44×44, контраст текста не ниже 4.5:1, светлая и тёмная темы обязательны); шкалу типографики (`caption`, `small`, `body`, `lead`, `title`, `display`); отступы (`xs`…`xxl`) и радиусы (`sm`, `md`, `pill`); палитру по ролям, а не по оттенкам (`bg`, `surface`, `surfaceAlt`, `ink`, `muted`, `line`, `accent`, `onAccent`, `core`, `ok`, `warn`, `danger`, `onDanger`) — для светлой и тёмной темы; реестр обязательных компонентов (`TopBar`, `Card`, `Button` primary/ghost, `Field`, `Pill`, `Progress`, `Empty`). Проект может сузить или дополнить общее своим блоком; сложение — «общее → локальное», противоречие видно, а не тихо побеждает.

Готово когда: глобальный экран «Дизайн» показывает эталон и список подключивших его проектов; проект получает по `GET /api/projects/:id/design` сложенные токены с указанием, откуда каждая часть; два проекта видят одни и те же значения.
