# Модель и справка: System Design по порядку

Зачем: порядок работает, только если модель раскладывает по нему, а человек о нём знает.

Что делаем:
- `grill-plan.md` и `inbox-plan.md`: из тем «Нагрузка» и «Надёжность и безопасность» — требования с `quality` и числом в «Готово, когда», к каждому числовому — проверка вида `metric`. Черновики решений по областям, повод которых есть (R-0124), — с разделом «Варианты», без выбора.
- `task.md`: код не меняет принятого решения архитектора; если задача упирается в область без решения — вопрос в конце, а не выбор.
- `architecture-audit.md`: находка `against_decision` — код расходится с подтверждённым решением архитектора; решения с `area` уходят в запрос.
- Справка `docs/18-architecture.md`: раздел «System Design в DocDD» — пять шагов на одном примере (рейсы и ведомость: 300 водителей, отчёт за 2 с, ведомость не теряется), какая запись на каком шаге, что напомнит консоль.

Чего не делаем: модель не выбирает ни одну из восьми областей.

Готово, когда: собранные запросы несут эти указания; раскладка допроса на подставной модели даёт требования с `quality`, проверки-метрики и черновики решений с вариантами; раздел справки есть, README и руководство ссылаются на него.
