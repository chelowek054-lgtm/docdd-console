# Экраны дизайна — HTML-макеты из Claude Design, привязанные к карте путей

Зачем: экраны рисуем в Claude Design, он отдаёт HTML. PNG-эталон теряет главное — ширины, темы, состояния; HTML показывает
экран живым и проверяется по токенам. Нужна вкладка «Экраны» в дизайне, куда эти макеты добавляются.

Что делаем:

1. **Формат.** Макет — `docs/development/design/mockups/<экран>/index.html` и рядом его файлы (картинки, шрифты, css);
   `<экран>` — id экрана из подтверждённой карты пользовательских путей. Макет оформляется **проектным документом**
   (`design`) с полями `screen: <экран>` и `mockup: design/mockups/<экран>/index.html`: у него есть статус,
   журнал и подтверждение, задача ссылается на него `documents` и не уйдёт в работу, пока макет не подтверждён.
   PNG-эталон (`mockups/<экран>.png`) остаётся валидным.
2. **Импорт.** На вкладке «Экраны» — «Добавить экран»: выбрать экран карты (или ввести новый id), загрузить HTML-файл или
   zip-экспорт Claude Design. Консоль раскладывает файлы под `mockups/<экран>/` (только внутри корня, без `..`,
   лимит размера), заводит черновик `design` и строку журнала. Повторный импорт черновика — новая версия поверх со
   строкой журнала; подтверждённый макет так не перезаписывается — заводится преемник (`supersedes`).
3. **Просмотр.** Список экранов карты путей с состоянием: «нет макета», «черновик», «подтверждён», «есть снимки». Макет
   открывается в изолированном `iframe` (`sandbox` без `allow-same-origin`; сервер отдаёт только файлы из
   `mockups/<экран>/`) на ширинах 375 / 768 / 1280, в светлой и тёмной теме (`data-theme` и
   `color-scheme`); рядом — снимок реализации той же ширины и темы, если есть.
4. **Сверка.** Предупреждения: `mockup_screen_unknown` — макет называет экран, которого нет в карте путей;
   `mockup_off_tokens` — в HTML цвета, которых нет среди токенов дизайна (с перечнем); `screen_mockup_missing` —
   экран возможности с приоритетом `must` без макета. Подтверждённый HTML-макет снимается в PNG тем же шаблоном
   скрипта снятия, что и экраны, и становится эталоном для проверки Responsive и Pixel-Perfect.

Чего не делаем: не редактируем HTML в консоли; не тянем макеты из Claude Design по сети — только файл, который положил
человек; не исполняем скрипты макета в контексте консоли.

Готово, когда: HTML из Claude Design добавляется на вкладке «Экраны» к экрану карты и становится черновиком `design`;
макет виден живым на трёх ширинах и в обеих темах рядом со снимком; подтверждённый макет держит задачу через
`documents`; предупреждения о неизвестном экране, цветах вне токенов и экране без макета видны в «Обзоре» и
`npm run check`.
