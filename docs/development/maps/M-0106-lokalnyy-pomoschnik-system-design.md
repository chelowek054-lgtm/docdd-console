# System Design: локальный помощник DocDD

Вкладка в каждом проекте DocDD работает напрямую с моделью на той же машине или в закрытой локальной сети. Пользователь задаёт вопросы по документам, прикладывает изображения, изучает источники и предлагает изменения в записях. Внешний харнес для этого сценария не нужен.

## Как проходит запрос

1. Сервер открывает сессию в выбранном проекте от имени вошедшего пользователя. Вкладка показывает выбранную локальную модель, готовность индекса и доступность веб-ресерча.
2. Сборщик контекста сначала использует запись или раздел, которые пользователь указал явно. При нехватке данных запускает гибридный поиск по словам и векторам. Он получает несколько подходящих блоков и сверяет права и текущую версию источников перед передачей модели. Ответ ссылается на ID записи и раздел либо на файл и страницу. Если данных мало, вкладка показывает этот пробел.
3. Изображение загружается как вложение сессии. Адаптер проверяет формат, размер и разрешение, затем передаёт изображение по API только настроенной локальной мультимодальной модели. OCR и описание, если включены, маркируются как производные и ссылаются на оригинал. Если модель не принимает изображения, вкладка показывает это и сохраняет текстовый режим.
4. Веб-ресерч включается пользователем для конкретного запроса. Шлюз отправляет согласованный поисковый текст, сохраняет URL и время получения, а извлечённый текст передаёт модели как внешний источник. Страницы не могут запускать инструменты. При отключённой сети локальные вопросы, изображения и доступные операции MCP продолжают работать.
5. Модель предлагает изменения через ограниченный набор инструментов MCP. Вкладка показывает документ, аргументы и diff. Шлюз применяет права пользователя и штатные правила DocDD. Для подтверждения, закрытия и приёмки требуется явный ответ человека. При смене ревизии сервер отклоняет устаревшую запись и предлагает пересчитать diff. У модели нет прямой записи в каталог документов.

## Хранение и границы доступа

- Документы в разрешённых источниках проекта остаются источником истины. Переиспользуем разбиение по заголовкам и семантический индекс DocDD, затем расширяем список источников до настраиваемого реестра документов. В первой версии индексируем Markdown и текст, а импорт PDF и других форматов подключаем отдельными адаптерами. Существующие настройки прав действуют и через поиск, и при открытии цитаты.
- Индекс отделён по проектам. Блок хранит ссылку на оригинал, заголовок, отпечаток содержимого и версию модели эмбеддингов. Переименования и удаления убирают устаревшие ссылки. Смена модели пересобирает индекс, который можно удалить и восстановить по документам. Если векторный поиск недоступен, остаётся поиск по словам.
- Папка сессии `.docdd/local-assistant/<session-id>/` содержит вложения, извлечённый текст и промежуточные черновики. Сервер выдаёт модели файловые операции только внутри этой папки. У каждой сессии есть срок хранения и лимит объёма. Сервер исключает эту папку из индекса документов и поставки по Git.
- Адреса моделей и права инструментов настраиваются сервером. Вкладка не передаёт модели ключи или токены. Локальный профиль не переключается автоматически на облачный API. Веб-шлюз отдельно ограничивает источники и не передаёт вложения, внутренние документы и секреты.
- Для фоновой переиндексации и долгих ответов переиспользуем журнал задач модели, если он поддержит отмену и видимый статус. В аудит пишем факт обращения к сети или записи, автора и результат операции.

## Порядок реализации

1. Локальная вкладка в режиме чтения. Выбор сервера моделей, наличие индекса, текстовый поиск и ответы с цитатами при отключённом внешнем интернете.
2. Вложения и локальная мультимодальность. Временная папка, лимиты, очистка и обработка изображения с сохранением ссылки на источник.
3. Веб-ресерч с отдельным разрешением и MCP с предпросмотром изменений. Проверить, что локальный режим сохраняется при отказе любого внешнего сервиса.

## Критерии проверки

- При отключённом интернете ответ по проекту содержит действующие ссылки на разделы. Поиск по точному ID работает при сбое эмбеддингов. Удалённая запись исчезает из выдачи после обновления индекса.
- Запрещённый документ из того же проекта и документ соседнего проекта не появляются в контексте, цитатах и результатах поиска. При изменении прав старый индекс не открывает доступ.
- Изображение попадает только на заданный локальный API. Веб-поиск получает только согласованный запрос. Скрытые инструкции со страницы не приводят к выполнению MCP.
- Изменение, предложенное через MCP, можно отклонить без правки документа. После подтверждения результат виден в журнале. Параллельная правка приводит к конфликту ревизий.
