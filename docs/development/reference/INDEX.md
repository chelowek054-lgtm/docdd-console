# Справочник проекта

Сгенерировано приложением, не править: источник — справки (S-…) и подтверждённая карта кода (docs/13-reference.md).

## Модули проекта
Что уже написано. Прежде чем заводить новое — посмотри, нет ли такого.

### Клиент — Интерфейс консоли на Nuxt и Vue: экраны, компоненты, переводы, состояние.
### Командная строка — Скрипты для проверки проекта, отчётов, замеров и обслуживания сервера.
### Сервер — Nitro-сервер: API, чистая логика разбора и проверки, служебные утилиты.
- `server/lib/scaffold.ts` — Заведение записей и формата: шаблоны, слаги, выдача номеров. Чистые функции над строками — папки создаёт маршрут.
- `server/lib/types.ts` — Общие типы ядра. Кода здесь нет намеренно: тип записи и код нарушения — часть контракта из docs/02-workspace-contract.md и docs/05-validation.md, и им нужно одно место, а не копия в каждом модуле.
- `server/utils/inbox-service.ts` — Входящее: сырые заметки и заведение записей по ним (docs/10-inbox.md). Записи создаёт приложение, а не модель: номера выдаёт оно, front matter и имена файлов — его работа.
- `server/utils/reference-service.ts` — Справочник проекта (docs/13-reference.md): справки и индекс. Индекс — производное от подтверждённых справок и карты кода; приложение собирает его и пишет в файл, руками он не правится.
- `server/utils/work-service.ts` — Выполнение задачи через клиент (docs/09-execution.md). Приложение заводит ветку, показывает дифф и сливает перемоткой — принимает человек.
- `server/lib/agents.ts` — Агенты ролей (R-0091, docs/adr/0033-role-agents.md): определение агента — файл проекта `docs/agents/<id>.md`, ограничения аккаунта агента — здесь, в коде консоли. Чистые функции:
- `server/lib/analyst.ts` — Помощник аналитика (T-0038): собирает запрос к модели по пакету контекста — само требование, соседние требования и термины глоссария. Приложение ничего не применяет: ответ читает человек (ADR-0008).
- `server/lib/architecture.ts` — Точная проверка архитектуры по карте кода: модули с публичным входом, слои, shared и kernel, подсказка «поднять»
- `server/lib/attachments.ts` — Вложения к прогону и дефекту (R-0099, docs/02-workspace-contract.md): скриншоты и логи лежат файлами в репозитории проекта рядом с отчётами — своей базы у консоли нет. Чистые функции:
- `server/lib/auth.ts` — Учётная запись приложения (docs/adr/0020-people-roles-permissions.md): не содержание проекта.
- `server/lib/course.ts` — История курса проекта (docs/07-maps.md, «Источник правды и история курса»). Своего хранилища нет: время и автор правки курса уже лежат в записи карты — в строке журнала, которой она получила `approved`.
- `server/lib/coverage.ts` — Покрытие процессом: что стоит за возможностью в проекте — требования, задачи, проверки и код (docs/07-maps.md, «Покрытие процессом»). Полей у возможности для этого нет:
- `server/lib/criteria.ts` — Критерии приёмки в теле требования (docs/15-team-platform.md, R-0015). Чистые функции над текстом: раздел «Критерии приёмки» → список критериев, из каждого — заготовка записи `verification`.
- `server/lib/custom-maps.ts` — Пользовательские карты (docs/adr/0028-custom-maps.md): определения из манифеста, вид одной карты из сложенной картины и текст черновика. Чистые функции — без файловой системы, их зовут маршруты и правила.
- `server/lib/design-catalog.ts` — Каталог историй как контракт (docs/16-design-system.md, «Storybook как контракт», R-0054, R-0055, R-0056). Консоль Storybook не запускает:
- `server/lib/design-constructors.ts` — Конструкторы форм и таблиц (docs/16-design-system.md, «Конструкторы»): по описанию полей или колонок отдают заготовку компонента выбранного стека на токенах дизайна и **заготовку словаря на каждый язык проекта** — как у…
- `server/lib/design-contract.ts` — Контракт компонента (docs/16-design-system.md, «Контракт компонента», R-0053): уровень, из чего собран, варианты, свойства, слоты, события. Состояния и слои остаются в `DesignComponent` как были.
- `server/lib/design-diff.ts` — Разница токенов дизайна у записи на подтверждении (R-0073): палитра «было / станет», контраст до и после, файлы выгрузки по стекам, которые поменяются.
- `server/lib/design-export.ts` — Выгрузка токенов дизайна в файлы темы четырёх стеков (docs/16-design-system.md, «Стеки и выгрузка») и сверка файла проекта с тем, что дала бы выгрузка. Чистые функции:
- `server/lib/design-figma.ts` — Импорт токенов из Figma Variables (docs/16-design-system.md, «Токены из Figma»): разбор ответа REST API `GET /v1/files/:key/variables/local` (или его части `meta`) в блок `docdd-design` и перечень расхождений с токенами…
- `server/lib/design-screens.ts` — Проверка экранов проекта моделью (docs/16-design-system.md, «Проверка экранов моделью»): опись снимков по экрану, ширине и теме, разбор ответа модели в находки. Чистые функции — файловая система и запуск модели снаружи.
- `server/lib/design-surface.ts` — Поверхности и вид (docs/16-design-system.md, «Поверхности и вид»): тени карточек, подложка страницы, мягкая заливка плашек и подписи капсом.
- `server/lib/design-theme.ts` — Конструктор тем (docs/16-design-system.md, «Цветовые темы»): чистые функции под экран.
- `server/lib/design.ts` — Токены дизайна (docs/16-design-system.md, ADR-0022, ADR-0023): разбор блоков `docdd-design` из подтверждённых `decision`/`design`, сложение «общее → локальное» с источником у каждой части и проверки — контраст по WCAG,…
- `server/lib/external-import.ts` — Импорт из внешних систем (T-0047, T-0048): выгрузка Jira (CSV/JSON) и страницы Confluence (HTML/Markdown) превращаются в заметки входящего.
- `server/lib/fix-diff.ts` — Предпросмотр починки «было → станет» (R-0072): план модели — таблица «Файл | Что меняем | Во что | Почему» (docs/prompts/fix-plan.md). Чистая функция:
- `server/lib/flow-groups.ts` — Группы на потоках данных (docs/07-maps.md, «Потоки данных», «Группы и здесь»). Своих групп у потоков нет: код берётся из групп кодовой карты, а источники сворачиваются по `kind`. Чистые функции — их считает экран.
- `server/lib/functional.ts` — Функциональная карта: состояние реализации, приоритет, связи между возможностями и то, что из них выводится (docs/07-maps.md, «Состояние реализации», «Приоритет и горизонт», «Связи между возможностями», «Что дальше и…
- `server/lib/glossary.ts` — Глоссарий проекта (T-0041). Формат — файл `docs/development/glossary.md`, строка на термин: `- **Термин** — определение` (тире, двоеточие или дефис). Решение о формате оформляется отдельной записью A- человеком.
- `server/lib/groups.ts` — Группы кодовой карты — уровень над модулями (docs/07-maps.md, «Группы: уровень над модулями»). Чистые функции над списками: их считает экран, а не сервер, и считает одним правилом, чтобы обзор и вид группы не разошлись.
- `server/lib/hierarchy.ts` — Исходные связи: стрелку всегда можно развернуть до опоры внизу.
- `server/lib/import.ts` — Импорт существующей документации. Приложение показывает, что нашло, и применяет утверждённый человеком план — предполагать за него оно не берётся (docs/adr/0003-no-llm-in-app.md).
- `server/lib/inbox.ts` — Разбор входящего: из сырых заметок — список предложенных записей (docs/10-inbox.md). Здесь только счёт над текстом: файлы читает и создаёт вызывающий.
- `server/lib/indexer.ts` — Поля, которые понимает контракт; всё остальное уходит в `extra` нетронутым.
- `server/lib/inventory.ts` — Опись файлов кода (docs/07-maps.md, раздел «Опись файлов»). Карта строится не «за один взгляд на проект», а по описи:
- `server/lib/knowledge.ts` — Пространство знаний (R-0016, docs/15-team-platform.md): заметки входящего как дерево страниц. Документы проекта сюда не входят — у них свои пункты меню (docs/04-ui.md, «Навигация»).
- `server/lib/layers.ts` — Слой модуля для экрана кодовой карты (docs/07-maps.md, «`layer` не обязателен»). Чистая функция:
- `server/lib/manager.ts` — Рабочее место менеджера (docs/15-team-platform.md, фаза 29). Чистые функции над записями индекса: доска, дорожная карта, вехи, сводка и вопросы помощнику. Ничего не хранится — всё считается из файлов проекта.
- `server/lib/manual-report.ts` — Ручная отметка «Проверено» (docs/02-workspace-contract.md, «Ручная отметка „Проверено“»): человек проверил сам, и приложение фиксирует это тем же отчётом, каким фиксируется любой прогон.
- `server/lib/map-diff.ts` — Разница карты на самой схеме (R-0069, docs/04-ui.md). «Было» — сложенная картина подтверждённых карт до этой записи, «станет» — она же вместе с ней. Чистые функции:
- `server/lib/maps.ts` — Карты проекта (docs/07-maps.md). Разбор трёх структур из тела записи и сверка свидетельств. Чистые функции:
- `server/lib/onboarding.ts` — Подключение проекта (R-0075, docs/04-ui.md, «Подключение»): чек-лист «Готовность проекта». Каждый шаг — одно, чего не хватает консоли, чтобы вести проект; статус не ставится руками, а вычисляется по состоянию проекта.
- `server/lib/order-diff.ts` — Общий вид «было → станет» для порядка (R-0072): предпросмотры порядка по важности и разбиения на фазы. Чистая функция — места считает сервер/библиотека, а не экран, чтобы три предпросмотра не разошлись в счёте.
- `server/lib/overview.ts` — Обзор проекта (docs/04-ui.md, «Обзор»): готово ли обещанное, что в проде, что делается и проверяется. Чистая функция над индексом — экран только рисует.
- `server/lib/permissions.ts` — Матрица «роль → действие» (docs/adr/0020-people-roles-permissions.md, п. 4). Чистые функции: проверяются без сервера. Манифест может права только сузить.
- `server/lib/phase-plan.ts` — Разбиение задач на фазы (docs/04-ui.md, «Разбить на фазы»). Чистые функции: какие задачи отдавать модели и что из её ответа можно завести. Номера и файлы — дело вызывающего, как и у входящего.
- `server/lib/portfolio.ts` — Строка портфеля (T-0042): сводка одного проекта из его индекса. Чистая функция — экран и проверка строятся на одном и том же, а файлов не читает.
- `server/lib/prompt.ts` — Сборка запроса к модели: шаблон из репозитория плюс данные проекта. Чистые функции над строками — сам шаблон приходит снаружи, а запуск модели живёт в `server/utils/llm.ts` (docs/adr/0008-llm-through-claude-code.md).
- `server/lib/record-diff.ts` — Разница «было → станет» для записи на подтверждении (R-0068, R-0070, R-0071). Чистые функции над строками: git и файлы живут в utils, чтобы это тестировалось без окружения.
- `server/lib/reviewer.ts` — Ревьюер задачи (docs/adr/0030-task-reviewer.md): кто её принимает. Явное поле `reviewer` побеждает; без него — правило по видам проверок и типу изменения. Чистая функция: ей хватает записей индекса и ролей манифеста.
- `server/lib/role-maps.ts` — Заготовки своих карт под роли (R-0087, docs/adr/0028-custom-maps.md): кнопка «Новая карта» предлагает их как отправную точку, дальше определение правится как любое другое. Чистые данные:
- `server/lib/search.ts` — Полнотекстовый поиск по записям и знаниям (T-0040). Обратный индекс «слово → документы» строится из текстов в памяти и пересобирается при смене отпечатка файлов: своей базы нет, всё производное (ADR-0001).
- `server/lib/source-detect.ts` — Автопоиск источников проекта (R-0077, docs/04-ui.md, «Подключение»): по списку путей файлов находит папки кода, клиента, документации и тестов; файлы контрактов, зависимостей и отчётов CI. Чистые функции над строками:
- `server/lib/strategy.ts` — Стратегический уровень и здоровье узла (R-0084, R-0085; docs/07-maps.md, «Стратегия и здоровье узла»). Стратегия — вид верхнего уровня функциональной карты, а не вторая сущность.
- `server/lib/task-order.ts` — Привести задачу в порядок прямо в карточке (docs/04-ui.md, «Запись»): выбор требования для `implements`. Чистые функции — файлы и сеть остаются снаружи.
- `server/lib/test-checks.ts` — Проверки из существующих тестов (R-0079, docs/04-ui.md, «Подключение»): находит тестовые файлы проекта, сопоставляет их с требованиями и предлагает проверки вида unit/integration с командой запуска; разбирает отчёт…
- `server/lib/verify-desk.ts` — Рабочее место тестировщика на «Сверке» (docs/04-ui.md, «Сверка — рабочее место тестировщика»): факт каждой проверки одним словом и пробелы покрытия. Чистые функции над индексом.
- `server/lib/work-order.ts` — Порядок работы по важности (docs/04-ui.md, «Порядок по важности»; docs/02-workspace-contract.md, «Порядок фаз»). Чистые функции над записями:
- `server/lib/workspace.ts` — Чтение проекта с диска. Всё, что читается здесь, дальше передаётся ядру строками и объектами: разбор и правила о файловой системе не знают.
- `server/utils/context-service.ts` — Пакет контекста для проекта (docs/adr/0021-context-pack.md): читает записи с диска и отдаёт их чистой функции. Список источников расширяется (`SOURCES`):
- `server/utils/design-screens-service.ts` — Снимки экранов и находки проверки (docs/16-design-system.md). Читает файлы внутри корня проекта: каталог снимков называет манифест, наружу корня путь не выходит (`resolveInside`).
- `server/utils/design-service.ts` — Токены дизайна проекта (docs/16-design-system.md, ADR-0022). Общие записи читаются тем же путём, что и правила из практик: источники `sources.shared` по тегам, только подтверждённое.
