# Проверка: статус legacy — переход, пачка, исключение и возврат в курс

Шаги: 1) перевод одиночной записи в legacy из разных статусов проходит, из draft — отказ, обратно — только в draft. 2) пачка по фильтру переводится одним действием с одной причиной, журнал пишет строку на каждую запись, тело не меняется. 3) причина с legacy_by: M-XXXX увеличивает счётчик «отправлено в legacy» в истории курса карты. 4) legacy-записи не входят в покрытие процессом, здоровье узла и предупреждения, не предлагаются в implements/affects, скрыты без переключателя «показать legacy» и видны с ним. 5) ссылки на legacy-запись остаются рабочими с пометкой, номер не переиспользуется, поиск находит запись. 6) кнопка «Перенести в текущий курс» заводит черновик requirement со ссылкой на исходную запись, саму её не меняя.
