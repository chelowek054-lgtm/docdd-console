# MCP: работа с проектом из ассистента

Консоль отдаёт проект ассистенту инструментами MCP. Решение и границы —
[A-0002](development/decisions/A-0002-mcp-tonkiy-sloy-nad-api.md), требование —
R-0107. Сервер — отдельный процесс `cli/mcp.ts` по stdio. Он ходит только в HTTP
API консоли, поэтому правила, права и журнал те же, что на экране.

## Подключение

Консоль должна быть запущена. Команда для Claude Code, из корня консоли:

```bash
claude mcp add docdd --env DOCDD_PROJECT=<id проекта> -- npx tsx cli/mcp.ts
```

| Переменная | Что значит |
|---|---|
| `DOCDD_PROJECT` | Обязательна: id проекта из списка консоли |
| `DOCDD_URL` | Адрес консоли, по умолчанию `http://127.0.0.1:3000` |
| `DOCDD_AGENT_TOKEN` | Токен агента. Без него и без `DOCDD_AUTH=on` на консоли — только чтение |

Токен выдаёт команда на машине консоли, живёт он шесть часов:

```bash
npx tsx cli/agent-token.ts <логин агента>
```

Агент должен быть в команде проекта (`team` в `project.yaml`). Смена статуса требует права `approve` (ADR-0020), поэтому для `move_task` нужна роль `qa` или `architect`: у роли `developer` такого права нет. Подтвердить документ агент всё равно не сможет: это запрещает ADR-0033.

## Инструменты

| Инструмент | Доступ | Что делает |
|---|---|---|
| `project_status` | чтение | Записи по типам и статусам, число нарушений |
| `next_tasks` | чтение | Задачи в работе и готовые с закрытыми зависимостями |
| `task_context` | чтение | Пакет контекста задачи |
| `list_issues` | чтение | Нарушения, сначала ошибки |
| `create_draft` | запись | Черновик записи |
| `add_journal_line` | запись | Заметка в журнал |
| `move_task` | запись | Только `ready → in_progress` и `in_progress → in_review` |

Инструментов подтверждения записи, закрытия задачи и слияния нет. Запись работает,
только когда консоль подтвердила вход и признала токен токеном агента: без входа API
не отличает агента от человека.

Ответ ограничен бюджетом: 6 000 знаков, у `task_context` 45 000. Необязательный аргумент
`budget` сужает ответ. Строка об отрезанном стоит сверху.

## Новый инструмент

Файл `server/lib/<модуль>/tools/<имя>.ts` с экспортом `McpTool` по умолчанию. Сервер находит
его сам, править `cli/mcp.ts` не нужно. Два инструмента с одним именем — ошибка запуска.
Новая возможность — свой каталог `server/lib/<модуль>/` со входом `index.ts`; снаружи
к нему обращаются только через вход (ADR-0013).

## Расход токенов

```bash
npx tsx cli/token-report.ts --task T-0183
```

Флаг `--baseline <файл>` записывает базовую линию, `--compare <файл>` сравнивает с ней на
один заход по видам запроса. Запросы, сделанные до появления `taskId` в учёте, идут как «вне задачи».
Расход самого ассистента, подключённого по MCP, консоль не видит: в учёт попадают только её собственные запросы к модели.
