# Локальная разработка: docker-compose база + override

Не про запуск самого DocDD Console (это `npm run dev`, без Docker) — общая
практика для проектов, у которых есть отдельный бэкенд и база, подключаемая
ими через `sources.shared` ([docs/11-shared-sources.md](../../../11-shared-sources.md)).

## Зачем это нужно

Без единого способа поднять стек локально каждый проект обрастает своим
набором команд и переменных окружения, и переключение между проектами
требует каждый раз заново вспоминать, как именно этот запускается.

## Что решили

- `docker-compose.yaml` — базовый, прод-подобный стек. Годится и для
  прод-подобного запуска: `docker compose -f docker-compose.yaml up --build`.
- `docker-compose.override.yaml` — оверрайд для локальной разработки:
  переключает сервисы на dev-цели с hot-reload. Подхватывается автоматически
  при обычном `docker compose up`.
- `.env.example` — шаблон переменных окружения в репозитории; настоящий
  `.env` — не в репозитории, копия с реальными значениями на каждой машине.
- Все значения конфигурации идут из `.env`, а не зашиваются в
  `docker-compose.yaml` напрямую.

## Чего не делаем

- Не коммитим настоящий `.env` с реальными значениями в репозиторий.
- Не заводим третий отдельный способ запуска «для тестов» или «для CI»,
  если хватает override с другими значениями `.env`.

## Что мешает

Ничего — паттерн уже используется одинаково в нескольких проектах
(InteractMed и другие), это описание существующей практики.
